# 3D Deep Research

沿时间找出改变路径的转折，在关键时刻还原主体与力量，再深入解释关键选择如何形成。三轴交汇要形成一条由各章证据共同支撑、可以检验的机制判断。这是报告的主要产出。

默认交付独立可打开的 HTML 报告。以 Markdown 写作，保留源稿便于复查与更新。HTML 使用石墨杂志版式、折叠目录和三级编号，需要 PDF 时从浏览器打印。作为其他研究流程的辅助方法时，按用户指定的主流程交付。

开始研究时读[证据协议](references/evidence-protocol.md)，写作时复制[报告模板](assets/report-template.md)，规划图表时读[视觉表达规范](references/visual-guidelines.md)。

## 执行流程

### 0. 定题与检索

明确对象、读者要理解或决定的问题、资料截止日和交付形式，建立一张简要研究底图。关注对象如何运转、哪些角色影响结果，以及哪些口径必须分开。只有未解决的信息会实质改变目标或判断时才追问。

先列出需要核实的事实、尚待解释的转折和可能推翻初始判断的材料。优先找原始记录、当事方行为、独立材料和失败案例。涉及当前状态时联网核实，记录发布与访问日期。输出位置采用用户指定目录，未指定时用当前项目的 output/。

按对象检查可能影响结论的维度，跨类型可组合使用。

| 对象 | 底图和复核重点 |
|---|---|
| 产品 | 用户任务、替代选择、采用与留存、定价与渠道、迁移成本。分别核对发布、采用与价值兑现。 |
| 公司 | 业务与客户、收入成本利润及现金、供需与渠道、组织治理与资本配置、制度责任和扩张条件。 |
| 技术或概念 | 定义、能力边界、工程实现、成本可靠性、集成维护和替代路线。优先找原始论文、标准与实现。 |
| 人物 | 同期公开行为、组织位置、关系资源和选择边界。用可核查记录分析动机。 |
| 事件 | 前因、触发、传播、各方响应以及当时可知的信息。检查未发生的预期变化和后见偏差。 |
| 行业或生态 | 价值链和利润分布、供需、多方竞争、制度和地域口径。核查上下游及非采用者。 |

### 1. 沿时间、主体与机制展开

1. **X 找转折。** 宽泛的公司研究从创立写起，专题从问题相关的起点写起。先在研究记录里分清发布、交付、采用和经营结果。正文按自然阶段组织，把有共同解释的细节点写进同一阶段。交代发生了什么，以及哪些选择因此改变。
2. **Y 回到关键时刻。** 从 X 选缺失后会削弱解释的截面。确认谁能决策、谁实际行动、谁改变了他方的资源或约束。比较各方怎样合作、竞争或制约，以及哪条证据能区分不同解释。
3. **Z 深入关键行动。** 从 Y 选出最需要解释的主体或力量，追踪当时的选项、激励与约束怎样形成行动，以及行动经什么环节影响结果。明确哪些环节见于原始记录，哪些仍属推断。
4. **三轴交汇。** 说明早期选择为何在后来特定主体与条件下产生某种结果，或者为何没有产生。形成一条结合三轴后才得到的判断，写清成立条件、最关键的未知和可观察的反证。证据只够支持条件性解释时，在正文和 A2 一并限定。

形成解释后做两次复核。先看证据是否需要改写前面的时间线或因果连接，再回到研究底图检查是否遗漏会改变结论的角色、经营约束或失败案例。复查失败、回退或有明确预期却未发生的节点。未能解决且会改变结论的缺口写入 A3。

### 2. 写作、审计与内容验收

按模板先给一句话判断和关键发现，再分章写发展路径、关键力量和内部机制。默认沿用模板的章名和顺序编号。第三章还原关键时刻怎样被各方的行动改变，第四章解释关键作用是怎样产生的。将具体判断写入小节标题。正文用同一个阶段或事件名称承接三章，只在便于阅读时加跨章链接。每段推动一个判断，具体说明谁做了什么、为什么、结果如何。数字首次出现说明时期、单位和口径。影响判断的限制写在相关判断旁边。

三轴交汇的判断通常放在第四章末尾，并在开头点明。只有问题涉及决策含义或未来变化、且有新内容时才留第五章。图表按解释价值取舍，核心比较依赖可比数字且图形明显更清楚时制作量化图。

正文关键事实紧邻来源引用，例如 [S01]。A1 记录来源身份和用途，A2 记录会改变核心结论的判断及交汇判断，A3 说明缺口。回到原文核对标题、摘要、每条关键判断和数字，记录必要的原文定位和复算依据。机制运行的证据与它对结果的贡献分别核查。证据不足时调整正文措辞并同步账本。

渲染前通读三章。确认 X 有路径变化，Y 写出了同期主体的行为与关系，Z 补出了能解释结果的环节，交汇判断确有解释增量。确认标题、摘要、正文和附录表达的判断强度一致。

### 3. 校验与交付

使用安装了 Python-Markdown 的 Python 构建。缺少该依赖时运行 pip install Markdown。

```bash
python [skill目录]/scripts/build_report.py report.md --require-xyz
```

命令在源稿目录生成 output.html 和核验用的 output.html.manifest.json。用户指定产物目录时用 --output-dir。历史问题导向报告可省略 --require-xyz，仍按当前证据契约校验。较早账本可用 validate_report.py 的 --legacy-schema 单独复核。

在浏览器打开 HTML，检查目录跳转、来源链接、章节编号、图表和窄屏布局。优先嵌入可核实的本地图片或自包含 SVG。交付 HTML，按需提供 Markdown 源稿或浏览器打印的 PDF。报告机器校验、事实审计和实际版面检查的结果。
