# 3D Deep Research

用证据链核实关键事实。用 XYZ 确定关键转折、查明推动与制约因素，并追踪核心因素对研究主体的影响。综合三轴形成可核查、可修订的研究判断。

默认交付**单文件离线 HTML（`output.html`）**，将交互式三维 XYZ 全景图与完整研究报告融合在同一文件中：打开默认首屏呈现全景图，通过顶栏「全景图 | 完整报告」切换视图，点击抽屉内来源或判断编号可无刷新跳转并高亮正文台账，切回全景图时保留视角与聚焦状态。禁用脚本或打印 PDF 时自动降级展示完整正文。保留 Markdown 源稿便于复查；用户指定只交付报告或分体交付时，按其要求执行。

开始研究时读[证据协议](references/evidence-protocol.md)，规划图表时读[视觉表达规范](references/visual-guidelines.md)。

## 执行流程

### 0. 判断是否触发

当用户要求分析、研究或调研，且希望得到需要系统取证和深入解释的研究报告时触发。根据问题复杂度和预期交付判断研究深度。查单个事实、解释概念或可简短回答的局部判断，直接回答。

### 1. 明确研究问题并启动检索

用户只给研究对象或宽泛目标，且不同方向会改变报告主线时，只询问一次。给出 2–3 个具体研究问题，用一句话说明各自的侧重点，并标明推荐项。收到选择后定题。用户已给出明确问题或授权自行定题时，直接推进。

明确研究对象、要回答的问题和资料截止日。把问题拆成待核实的事实和待解释的变化，按[证据协议](references/evidence-protocol.md)确定谁可能留下记录、去哪里查原文。找到足以界定待比较状态或待解释变化的材料后开始分析。

检索贯穿分析、写作和回源核验。遇到证据缺口、来源冲突或可能改变结论的新解释时，针对具体问题补查原文，并据此更新分析表、判断和账本。

### 2. XYZ 分析

在研究笔记中建立 XYZ 分析表。每个需要解释的关键转折或已核实观察占一行。按[证据协议](references/evidence-protocol.md)边分析边检索。新证据改变转折或解释时，更新、拆分或补充相应行，并同步账本。

| X 关键转折（如适用） | Y 推动与制约因素 | Z 对研究主体的影响 | 证据与待查问题 |
|---|---|---|---|
| 时间、前后变化、可观察结果 | 核心因素、作用方向、主要替代解释 | 作用路径、成立条件、对主体的结果 | 来源和判断编号、待查问题、可查材料 |

逐行将 X、Y、Z 写到证据能支持的范围，在关键事实和判断旁标注对应的 S、C 编号。证据不足处写清缺口。

交付含全景图的单文件报告时，按[全景图规范](references/panorama.md)将 XYZ 分析表整理为 `xyz.json`，与报告账本同步。

#### X · 确定关键转折

按时间梳理发展过程，选出改变路径或后续选择的节点。记录发生时间、前后变化和可观察结果。影响判断时，分别核实公布、交付、实际采用和经营结果。从影响答案的时间起点写起。静态比较或机制研究没有相关转折时，在 X 栏注明「无相关转折」，记下已核实的差异或现象，供 Y、Z 分析。

#### Y · 查明推动与制约因素

对照 X 的关键转折，查明什么促成了变化，什么阻碍了变化，什么改变了它发生的时间、方向或规模。静态比较和机制研究查明造成差异或维持现象的因素。核实相关方的行动及同期条件，比较主要的替代解释，按证据判断核心因素和作用方向。同一节点包含需要分别解释的变化时，返回 X 拆分。

#### Z · 追踪核心因素对研究主体的影响

从 Y 的核心因素出发，追踪它通过哪些环节影响研究主体。结合研究问题写明影响方向、成立条件和结果。涉及相关方行动或主体应对时，写入对应环节。分别核查作用过程是否发生，以及结果在多大程度上可归因于该因素。标明仍待验证的环节和结果。

#### 综合 XYZ · 形成研究判断

综合表中各行，写出对研究问题的初步回答。复核影响判断的关键角色、现实约束和反例。将核心判断、成立条件和会改变判断的证据记入 A2。

#### 判断何时转入写作

当核心判断已有可回源的证据、主要替代解释已核查时，逐项问「还能查到什么，会改变哪条判断、因素主次或成立条件？去哪里找？」有可能改变判断且有具体线索可查时，继续补查。完成可行的检索后仍有关键缺口时，收窄判断或标明未决，并将已查范围及缺口对答案的影响记入 A3。能交代清楚当前证据支持的答案与未决问题时，开始拟提纲。写作和审计发现新的关键缺口时，回表补查。

### 3. 写作、审计与内容验收

从 XYZ 分析表提炼一句话答案，列出支撑它的分论点，按读者理解答案所需的顺序排成提纲。用分论点写标题，为每节列出要论证的要点、对应证据和限制。同一节可调用多行中的 X、Y、Z。

按提纲使用[报告模板](assets/report-template.md)成文。开头给核心结论和关键发现。正文段落按[报告样式](assets/report.css)统一首行缩进 2 个汉字宽度。每段推进一个要点，写清关键变化、原因或结果，并在相关判断旁交代限制。数字首次出现时说明时期、单位和口径。需要用图表解释比较或机制时，按[视觉表达规范](references/visual-guidelines.md)制作。

正文关键事实紧邻来源编号，例如 [S01]。从标题、摘要和正文逐条核对核心判断，找到研究表中对应的 A2 判断，再按 A1 的位置回查引用的原文。确认对象、口径、置信度和适用范围一致。复算关键数字，分别核查作用过程和可归因的结果。证据不足时收窄正文判断，并同步研究表、A2 和 A3。

关键判断完成回源、足以改变结论的冲突和缺口已核查或已在正文限定后，结束检索。渲染前确认各节都支撑研究问题的答案，标题、摘要、正文和附录的判断强度一致。

### 4. 校验与交付

将 `report.md` 和 `xyz.json` 放在同一目录，用[构建脚本](scripts/build_report.py)生成单文件 HTML。缺少 Python-Markdown 时运行 `pip install Markdown`。

```bash
python [skill目录]/scripts/build_report.py report.md
python [skill目录]/scripts/build_panorama.py xyz.json --report report.md --check
```

默认命令生成内含三维全景图与完整报告的单文件 `output.html` 及核验用的 `output.html.manifest.json`。每份报告使用独立目录。可通过 `--xyz` 指定数据文件，通过 `--output-dir` 指定输出目录；需要额外输出独立 `panorama.html` 时加 `--split-panorama`；只交付静态报告时加 `--report-only`。沿 XYZ 分章的旧稿可加 `--require-xyz` 检查原章节结构。较早账本可用[结构校验脚本](scripts/validate_report.py)的 `--legacy-schema` 单独复核。

将 `output.html` 复制到空目录离线打开，检查默认全景图首屏、顶栏切换、抽屉引用跳转至 A1/A2 台账以及禁用脚本/打印 PDF 降级效果。联网检查需要访问原文的来源链接。图表使用可嵌入的本地图片或自包含 SVG。按需提供 Markdown 源稿或浏览器打印的 PDF。
