# 3D Deep Research

先建立研究底图，确认研究对象的边界、运转方式和当前状态；再用 X/Y/Z 逐层解释：X 识别显性与非显性的关键变化及其后续影响，Y 沿具体变化切开并比较成因，Z 拆开尚不清楚的作用连接。分析结果持续返回发展路径和研究底图，用证据校正解释并检查重要遗漏。

本 Skill 为主研究流程时，默认交付完整的 Markdown、HTML 和 PDF 三份报告；用户明确缩小交付范围时按其要求减少。用户点名其他研究 Skill 或选择其他工作模式时，以其作为主流程；仅在需要本方法时辅助使用，不叠加独立默认产物。不要仅因通用的 deep research 字样同时运行两套流程，也不要把普通问答扩写成长报告。

## 资源读取

按当前阶段读取所需资源；同一任务中已完整读取且未变化的文件直接复用。输出被截断时只补读缺失部分，不反复装载全文。

1. 读取 [references/evidence-protocol.md](references/evidence-protocol.md)，建立来源与 Claim 账本并执行事实审计。
2. 读取 [references/xyz-method.md](references/xyz-method.md)，建立研究底图并执行 X/Y/Z、路径校正和覆盖复核。
3. 根据研究对象读取 [references/object-adapters.md](references/object-adapters.md) 的对应部分。
4. 分析时读取 [references/visual-guidelines.md](references/visual-guidelines.md)，规划有解释价值的图；论点稳定后制作和检查。
5. 写作时复制 [assets/report-template.md](assets/report-template.md)，保留元数据与证据附录，按核心问题组织正文。
6. 首次构建或排错时读取 [references/build-runtime.md](references/build-runtime.md)。运行现有脚本，无需预读实现；仅在明确故障需要时定位相关代码。

## 报告措辞

以下规则适用于正文、标题和图注；证据附录以准确、可追溯为先。

- 先直接回答研究问题，再解释依据、原因及其对用户问题的含义；用户未要求行动方案时，不自行扩成路线图。
- **先具体，后抽象。** 优先说清谁做了什么、发生什么变化，再解释背后的概念。能直接说明的，不用抽象名词代替。
- **先判断，后解释。** 一句话先说清主要意思，原因和必要限制随后展开，避免把多层意思挤进一句话。
- **面向目标读者使用准确、克制的专业书面语。** 保留必要概念，用具体对象、关系和口径解释；不用口语化比喻替代分析，也不用抽象术语增加专业感。
- 每个核心论点说明目前支持什么判断、为什么重要、依据及作用过程是什么。每段推进一个判断；删除不增加事实、解释或决策价值的句子。
- 明确区分事实、解释和预测。证据只能支持“可能”时，不写成“证明”或“必然”。
- 不把 Claim 类型、证据门槛、X/Y/Z 等内部方法术语写进正文；它们只用于组织研究和附录说明。
- 数字首次出现时说明时间、单位、统计口径和比较对象。
- 不使用宣传式形容词、无依据的最高级，以及“值得注意的是”“不容忽视”等空洞过渡语。
- 影响判断方向、适用范围或幅度的限制紧邻相关结论；共性研究限制放入 A3，不逐段重复。同一论证只完整展开一次。
- 证据不足时，明确可支持的暂定判断和仍未解决的部分。不用反复强调“不能证明”“不等于”代替分析；证据无法区分因素重要性时不强排主次、不编造贡献比例。

表达示例（只示范论证方式，变量须按具体研究取舍）：

| 只有提醒的表达 | 增加分析的表达 |
|---|---|
| 高售价不等于高利润 | 增量利润取决于售价差、增量制造与售后成本，以及对既有机型的替代。 |
| 看得更多，未必做得更好 | 大屏的使用收益取决于任务布局与输入成本。 |
| 兼容不等于适配好 | 应分别检查布局利用、状态连续性和关键操作完成情况。 |

## 执行流程

### 0. 明确研究设定

根据用户问题和上下文明确目标读者、需要作出的判断、研究对象及类型、时间基准、范围和交付要求。无法从上下文解决且会显著改变目标或正确性的问题才追问；其余情况直接开始。形成暂定问题结构，指出最可能改变判断的未知项，再根据对象适配器建立研究底图、检查遗漏；证据可以推翻暂定结构。

必须检查的维度不等于必须写入正文的章节。篇幅按对核心问题的解释价值分配，不按类别平均分配；重要性判断须有依据，无关侧面省略，证据不足但可能改变结论的侧面进入 A3。

复杂或持续时间较长的任务可以把上述设定记录为工作笔记；不要为简单任务强制创建独立过程文件。

研究范围由用户问题和证据决定，不追求来源数、Claim 数、字数或图表数量。每个进入 A2 的关键判断和数字都必须通过适用的证据门槛并完成审计；资料不足时缩小可确认结论的范围，保留未解决问题，不静默改变用户的研究目标。

涉及“最新、现在、最近”时联网核实，并记录发布日期和访问日期。输出到用户指定位置；未指定时使用当前项目的 `output/`。

### 1. 规划检索

围绕底图事实与口径、关键变化、候选成因、待解释连接，以及反向证据和失败案例规划检索。依 evidence protocol 优先选择适合对象的原始材料、官方记录和独立来源。随证据调整问题；影响结论的问题最终要有来源支持，或在 A2/A3 标为未解决。复杂任务可维护已有笔记，不强制新增表格。

### 2. 维护证据账本

在 `report.md` 附录 A1 和 A2 分别维护来源与 Claim 账本。来源使用稳定 ID（`S01`、`S02`），关键判断使用 Claim ID（`C01`、`C02`）。普通事实在正文引用来源，只有影响核心结论的判断进入 A2。更新时读取并修改相关记录和段落，避免反复输出整份账本。

按 [references/evidence-protocol.md](references/evidence-protocol.md) 持续记录关键判断的支持、反向材料、独立性、置信度、缺口与修订条件；因果和机制分别记录过程证据与归因边界。

证据不足时交付“已确认部分 + 资料缺口 + 下一步验证路径”。因果或机制证据不完整时降级表述，不补写猜测，也不因局部缺口停止整份交付。

### 3. 建立底图并执行 X/Y/Z 分析

按研究底图建立暂定变化路径，区分可观察变化、状态改变和后续影响；围绕核心判断比较成因、拆解作用过程，再据证据修正节点、解释与全局覆盖，不机械单向完成 X、Y、Z。

复杂研究可在已有工作笔记中维护节点、待解释问题、因素、作用连接和证据状态的对应关系，不要求独立过程文件。X 定位变化，Y 比较原因，Z 补出缺失的中间环节、条件或可观察后果；这些是分析分工，不是正文章节。详细方法和未来表达见 [references/xyz-method.md](references/xyz-method.md)。

重要判断紧邻 `[S01]` 来源引用。解释须说明因素如何造成变化及后续影响，以及最可能使判断失效的前提；深度由解释缺口决定，不按节点数或层数执行。

分析时规划核心比较、路径和机制的视觉表达，随证据调整；可在已有笔记简记，无需独立账本。

### 4. 写作与视觉表达

使用 [assets/report-template.md](assets/report-template.md) 的元数据与必要附录。默认按“核心回答—必要背景—有主次的核心论点—对研究问题的含义”组织正文。在每个论点内连续解释事实、原因、机制与边界，摘要只提炼判断，其他位置补充新证据或交叉引用。历史演化本身是核心问题时才使用演化式目录，不补写无关历史。重组不免除证据审计、解释追踪和双重回返。

关键关系用图能显著减少读者对照、记忆或推演负担时，应制作相应分析图；数量由需要解释的关系决定。不能以正文已有描述或缺少量化数据为由省略有价值的图。图、表与文字各取所长，避免重复和装饰。量化图必须有可靠且可比较的数据；具体触发条件、证据要求和图表契约见 [references/visual-guidelines.md](references/visual-guidelines.md)。

### 5. 执行事实审计

结构校验不能证明事实。验证前按 evidence protocol 执行归属审计和数字复核：

1. 回到来源原文，确认每个关键判断能够由所引材料推出；
2. 复算正文数字，检查单位、币种、时间和统计口径；
3. 确认反向材料与正文中的限制一致，没有被删除或弱化；
4. 检查 X 中的可观察变化没有被候选解释替代，Y 中的因素都指向明确节点，Z 中的机制没有停在术语或同义扩写；
5. 返回研究底图，检查商业模式、经济性、竞争、治理、制度责任或其他对象适配器提示的重要侧面是否因主线过强而被静默删除；
6. 把审计结果反映到正文、A2 和 A3。

审计失败时改写正文，或降级、删除 Claim；不修改账本去迁就结论。

### 6. 内容验收

事实审计后、渲染前通读正文，逐项检查：

1. 开头是否直接回答用户问题，给出目前最有支持的判断和必要边界？
2. 核心因素是否有主次及依据；无法排序时，是否说明缺少什么区分证据？
3. 每节是否增加事实、比较、解释或决策含义；是否重复展开同一论证？
4. 正文结论是否与来源、反向材料、A2/A3 的范围和强度一致？
5. 概念、措辞和解释深度是否适合目标读者？

未通过时修订相关段落，不靠增加篇幅、来源或图数补救，也不为简洁删掉重要反向证据。在已有工作记录简记检查结果和修订，不新增长评审报告。按 visual guidelines 复核图的解释价值，全文无图时执行零图复核。结构检查不能替代本步骤。

### 7. 构建与交付

内容稳定后使用统一入口，默认生成 HTML、PDF、产物校验和分页预览：

```bash
python [skill目录]/scripts/build_report.py report.md
```

首次配置与精简交付命令见 [references/build-runtime.md](references/build-runtime.md)。构建入口复用已验证的运行环境，调用原有 `render_report.py` 和 `validate_report.py`，保留 WeasyPrint 69.0、[assets/report.css](assets/report.css)、指定字体和证据契约。独立结构检查仍可运行 `python [skill目录]/scripts/validate_report.py report.md`；它不证明事实、论证质量或版面正确。

新报告使用 `证据契约：3`。历史报告的 `--legacy-schema` 不得用于绕过新交付失败。保留 HTML/PDF 同名 `.manifest.json`；仅当输入、资源及构建代码未变化且校验通过时复用产物。内容或资源变化后重建。渲染阶段用局部修改，不重复生成整份正文；脚本正常时只读取状态摘要，错误时再读日志。

PDF 只通过本 Skill 的渲染器生成，不切换引擎或排版实现。依赖、字体或预览工具不可用时完成可行且已授权的修复；仍阻塞则交付已通过适用检查的 Markdown/HTML，明确 PDF 或视觉检查尚未完成，不能把部分交付称为完整交付。

标题取第一行 H1，`[Sxx]` 在 HTML/PDF 中转为可点击引用。查看预览联系表，再放大封面、代表性正文、图表页及末页；必要时扩大检查，确认无裁切、重叠或缺字。完整交付仍含 `report.md`、`output.html`、`output.pdf`，用户明确缩小范围时按其要求。

## 质量红线

- 不把新闻排序当作因果链，也不把力量分类表当作 Y 轴。
- 不把待验证的解释当作节点事实，不用心理揣测代替机制。
- 不把合理机制直接当作本案例中已证实的原因，不用术语或同义扩写冒充机制拆解。
- 不让单一解释主线挤掉会改变结论的重要业务、经济性、竞争、治理或制度侧面。
- 不用同一原始材料的转载数量冒充独立证据。
- 不隐藏冲突、样本偏差、访问失败、资料缺口或反向材料。
- 不生成没有数据口径的数字图，不交付未经复核的数字。
- 不留下模板占位符、未渲染图表或无法追溯的来源。
- 不把过期证据当作当前状态。
