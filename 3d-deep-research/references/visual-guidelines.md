# 视觉表达规范

## 决策原则

每张图必须回答一个真实的分析问题，并且比正文或表格更容易理解。图形不能只用于装饰、填充版面或展示方法框架。

不设置数据图与结构图的固定配比，也不要求混合问题必须同时制作两张图。是否配图取决于问题和证据。

## 数据图触发器

同时满足以下条件时，必须制作至少一张能够支撑该判断的数据图：

1. 报告包含承重的定量比较、时间趋势或构成变化；
2. 存在至少两个口径可比的数据点；
3. 数据能够绑定 Source ID，并说明时间、单位和统计口径。

纯结构图、定性矩阵和表格不能替代已触发的数据图。

数据图必须呈现真实数值或刻度，并标明：

- 比较对象或时间范围；
- 单位与统计口径；
- 数据来源编号；
- 必要的数据限制。

多个相关定量问题可以合并进同一张图，但图表必须能清楚回答对应问题。

没有满足触发条件的定量问题时，允许零张数据图，并在附录 A4 说明原因。不得为了制作数据图而编造分值、补齐数据或混用不可比口径。

## 图形选择

| 分析问题 | 优先图形 |
|---|---|
| 数量、构成或对象比较 | 柱状图、条形图、散点图、构成图 |
| 指标如何变化 | 折线图、阶段趋势图 |
| 路径如何演化 | 时间轴、阶段演进图、关键转折链 |
| 多方力量如何作用 | 力场图、利益相关方网络、压力—响应图 |
| 机制如何运转 | 因果链、反馈回路、约束结构图 |
| 未来变量如何组合 | 驱动变量地图、2×2 情景矩阵、领先指标表 |
| 三轴如何交汇 | 因果汇流图、路径—力量—机制模型 |

有可靠、可比较的数据才制作数据图。没有数据支撑的关系可以使用结构图，但不得伪装成量化结果。

## 图表契约

每张图必须包含：

1. 唯一编号和能够说明问题的标题；
2. `figcaption`；
3. 支撑数值、节点或关系的 Source ID；
4. 图后解释段，说明主要发现和证据边界；
5. SVG 的 `viewBox`、`role="img"` 和 `aria-label`。

数据图还必须标明单位、时间范围和统计口径。结构图的关键节点与箭头必须有证据支持；没有反馈闭环时不要称为“飞轮”，没有方向证据时不要强行添加箭头。

优先使用 `figure`、inline SVG 或已渲染图片。最终报告不得保留 Mermaid 源码。

## 数量原则

不设置固定图表数量。满足数据图触发器时必须制作对应数据图；其他图表只有在降低理解成本时才保留。

零张结构图是合法选择。不能明确说出“这张图回答什么问题”的图应当删除。

## HTML/PDF

使用 [../assets/report.css](../assets/report.css) 的红灰体系。SVG 文本不要过密，关键字号在 A4 页面上应保持可读。表格和图形使用 `break-inside: avoid`，超长内容允许自然分页。

PDF 生成后渲染封面、首个正文页、图表页和末页进行检查。确认中文字体、数值标签、裁切、重叠、空白图、页眉页脚和编号正确。

## 飞书

复杂 inline SVG 在飞书 Markdown 导入中可能丢失属性或正文。飞书在线文档使用去除复杂 `<figure>...</figure>` 的副本，并在对应位置注明“完整图表见 PDF”；PDF 保留完整视觉版本。发送后回读在线文档，确认标题、正文、来源和关键结论存在。
