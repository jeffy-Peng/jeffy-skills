# 视觉表达规范

## 选择原则

每张图必须回答一个分析问题。图形不能只为装饰、填充版面或显得高级。

> 「选数据图还是结构图、各配多少」的决策层规则以
> [chart-allocation.md](chart-allocation.md) 为准（F/R/M 问题分类、配比护栏、
> 两条绑定规则）；本节表格只负责在该决策之后按分析问题挑选具体图形。

| 分析问题 | 优先图形 |
|---|---|
| 路径如何演化 | 时间轴、阶段演进图、关键转折链 |
| 多方力量如何作用 | 力场图、利益相关方网络、压力—响应图 |
| 机制如何运转 | 因果链、反馈回路、约束结构图 |
| 对象如何比较 | 二维矩阵、能力矩阵；只有口径可比时使用 |
| 证据强弱如何分布 | Claim 证据矩阵、置信度热力图 |
| 未来变量如何组合 | 驱动变量地图、2×2 情景矩阵、领先指标表 |
| 三轴如何交汇 | 因果汇流图、路径—力场—机制三栏模型 |

有可靠、可比较的数据才做柱状图、折线图、雷达图或气泡图。数据不足时使用结构图，不编造分值。

## 图表契约

每张图必须包含：

1. 唯一编号和回答问题的标题；
2. `figcaption`；
3. SVG 的 `viewBox`、`role="img"` 和 `aria-label`；
4. 图后解释段：说明关键关系、最大不确定性和证据边界；
5. 支撑节点、方向或数值的 Source ID。

优先使用 `figure` + inline SVG 或已渲染图片。不要在最终报告留下 Mermaid 源码；使用 Mermaid 时先渲染成 SVG。

图中只画有证据支持的关系。没有反馈闭环时不要命名为“飞轮”；没有方向证据时不要强行添加箭头。

## 数量

图表数量由问题复杂度决定：

- 简短对象：0-3 张；
- 标准公司/产品/技术分析：2-6 张；
- 长历史或多方博弈：4-8 张。

零张也是合法选择，但需说明图形没有信息增量。避免为满足固定预算而作图。数据图与结构图的配比护栏见 [chart-allocation.md](chart-allocation.md) 第三步。

## HTML/PDF

使用 [../assets/report.css](../assets/report.css) 的红灰体系。SVG 文本不要过密，关键字号在 A4 页面上应保持可读。表格和图形使用 `break-inside: avoid`，但超长内容允许自然分页。

PDF 生成后渲染封面、首个正文页、含表格或图表页、末页进行视觉检查。检查中文字体、裁切、重叠、空白图、页眉页脚和编号。

## 飞书

复杂 inline SVG 在飞书 Markdown 导入中可能丢失属性或正文。飞书在线文档使用去除复杂 `<figure>...</figure>` 的副本，并在对应位置写“完整图表见 PDF”；PDF 保留完整视觉版本。发送后回读在线文档，确认标题、正文、来源和关键结论存在。
