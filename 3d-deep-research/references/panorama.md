# XYZ 全景图

默认内嵌于单文件 HTML 报告。使用 PR #48 的整屏等轴画布、因素线和详情抽屉。初次打开呈现完整三轴，可旋转、缩放、过滤或切换到因素平面、影响剖面和俯视。X 排列转折或观察，Y 展示推动与制约因素，Z 展开核心因素如何影响研究主体。

## 数据约定

研究问题、标题和资料截止日取自报告。时间研究按转折顺序排列 X。静态比较或机制研究用 mode 为 comparison 的观察节点，省略 time。位置和轴距只用于表达结构。量化结果在报告中标明口径、单位和来源。

每项 Y 属于一个 X。确认跨 X 的多个站位是同一因素时，给它们填写相同的 series，每个 X 下同一系列最多出现一次。时间研究连起该系列的站位。每条 Z 指向同一 X 下实际参与的一项或多项 Y。图上每个 X 对应一个 Z 汇总节点，点开可分别查看每条路径、成立条件和证据。点开因素时只显示与该因素关联的路径。

```json
{
  "mode": "timeline",
  "xs": [
    {"id":"X1","time":"2026.05","title":"早餐提前营业","detail":"由八点改为七点","cites":["S01"]}
  ],
  "factors": [
    {"id":"Y1","x":"X1","name":"通勤提前","kind":"推动","detail":"提前经过门店的通勤客增多","cites":["S01"]}
  ],
  "impacts": [
    {"id":"Z1","x":"X1","factors":["Y1"],"claim":"C01","path":["增加早段到店机会","早餐订单增加"],"condition":"适用于通勤客较多的工作日","cites":["S01"],"pending":false}
  ]
}
```

- 节点编号全图唯一，由字母开头，可含数字、连字符和下划线。
- Y 的 kind 填推动、制约或待查。因素待查时，写清证据缺口，来源可为空。
- Z 的结果及证据边界直接取自 A2，来源须登记在 A1 并支持该条 A2。证据不足时填 pending 为 true，并标明待验证的环节。没有可用 A2 判断时填 claim 为 null，来源可为空。
- 有已核实的 X 但缺少可列入的 Y 或 Z 时，相应数组允许为空。图中标明待查。

## 构建与验收

```bash
python [skill目录]/scripts/build_report.py report.md
python [skill目录]/scripts/build_panorama.py xyz.json --report report.md --check
```

使用独立输出目录时，验收命令加 -o <输出目录>/output.html。需要独立图时，构建加 --split-panorama，验收加 -o <输出目录>/panorama.html，同时核对内嵌图与独立图。修改证据或判断后，同步正文与 XYZ，再重建交付文件。报告入口直达全景图，图上编号跳至 A1 或 A2。联合校验检查数据、账本和版本。事实与因果归因按证据协议回源。

离线检查四种视角、因素筛选、详情路径和资料跳转，复核移动端布局。关闭 JavaScript 或打印时，检查文字版仍保留全部路径、条件和证据编号。
