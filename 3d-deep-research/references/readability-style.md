# 可读性补丁：分层降密度写作规范

> 适用范围：在 3D Deep Research 模板与证据体系基础上执行。
> 本补丁只改表达层，不改严谨性：来源账本、Claim 矩阵、置信度分级、
> 反证条件全部保留在原位（附录），一个字不删。
> 目标：读者不读附录也能顺畅读完正文；要核查时知道去哪查。

## 核心原则：严谨归附录，顺畅归正文

把报告分成两层：
- 正文层：对"想知道结论和理由"的读者负责，追求一次读懂；
- 附录层：对"想挑战结论"的读者负责，保留全部证据纪律。
两层都完整，但各说各的话。正文不为附录做现场解说。

## 规则一：正文去术语化（翻译表）

框架术语只允许出现在附录与图表脚注。正文按下表翻译：

| 禁说（框架黑话） | 改成（人话） |
|---|---|
| load-bearing / 承重判断 | 关键结论 / 直接说结论本身 |
| 置信度：中高 | 这个判断比较扎实 / 这一点仍有变数 |
| 按 shared-origin 降级 | 这几家数据互相引用，只能算一个来源 |
| 按时间相关处理，不伪装因果 | 两件事同时发生，但未必是谁导致谁 |
| 证据门控未通过 | 目前证据还不够，先存疑 |
| 反证条件是…… | 如果将来出现……，这个判断就得改 |
| user-voice 样本 | 访谈对象主要是……（说明样本边界即可） |
| 因果/机制/市场/未来判断（类型标注） | 正文中不出现，只留在附录 Claim 矩阵 |

例外：正文首次引用某个方法概念且有助于理解时，允许用括号给一句人话注解，
随后不再重复术语。

## 规则二：限定语集中化

- 正文的句子保持完整陈述，句尾不挂"置信度/反证条件/证据等级"尾巴。
- 每章末尾设一个小结块「本章判断的成色」，3–5 行，集中交代：
  哪条结论最扎实、哪条仍有变数、什么证据出现时要修正。
- 完整的置信度与反证条件仍以附录 Claim 矩阵为准，小结块只做索引和摘要，
  不与矩阵冲突；冲突时以矩阵为准。

## 规则三：叙事先行

- 章节标题用问题，不用框架词：
  "携程的钱从哪来" ✓；"关键力场分析" ✗。
  （六个一级章节的顺序和数量不变，标题措辞可以人话化。）
- 每章开头用 2–3 句给出"人话版结论"，再展开论证。
  读者是被问题牵着走的，不是被框架推着走的。
- 三轴、账本、门槛等方法概念只在方法附录交代，正文不解释方法论。

## 规则四：行文层硬指标

- 正文段落 100–250 字；超过 300 字的段落必须拆。
- 每段只承载一个判断；一段里出现"第一/第二/第三"时考虑拆段或改表格。
- 允许使用口语铰链："换句话说""问题的关键在于""先说结论"。
- 数字第一次出现时给参照系（"624 亿元，约为 2019 年的 1.75 倍"），
  不让读者自己心算。
- 全文通读一遍：任何一句需要读两遍才能懂的，改写或拆开。

## 规则五：交付前自检清单

- [ ] 正文（不含附录）中搜索不到禁说术语表的左列词条
- [ ] 每个一级章节末尾有「本章判断的成色」
- [ ] 章节标题全部是问句或问题式短语
- [ ] 无超过 300 字的正文段落
- [ ] 随机抽 3 段，每段只表达一个判断
- [ ] 附录 Claim 矩阵完整，未因正文简化而删减任何字段
