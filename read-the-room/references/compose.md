# 话术、探针与禁忌

判断做得再准，用户带走的还是**那几句话**。这份协议规定怎么把判断变成可以直接说出口的原话。

## 一、话术的三条硬要求

1. **必须是原话，不是方向。** ✗"你可以适当表达你的诚意" ✓"王总，价格我按年框再让 3 个点，前提是这周能把技术确认走完——这样我这边也好排期。"
2. **话术要写作用与风险。** 每条后面附：它推进哪一环、对方可能怎么回、最坏情况怎么兜。
3. **话术要短。** 说出口超过 3 句的"话术"，用户在使用时一定会变形。给 1–3 句，剩下的留给他自己的语气。

## 二、三类话术

### A. 推进型（已知卡点，去推）

结构：**具体动作 + 具体时间 + 给对方留退路。**

- "如果这周四之前把技术确认走完，我这边七月排期就能锁上。您看这个节奏行吗？"
- "我先按 A 方案做一版给您内部看，不合适我们再改——您觉得先给谁看比较合适？"

要点：把推进变成对方"只需点头"的小动作，而不是"需要决策"的大动作。

### B. 探针型（有未知，去问）

设计纪律：**每个探针必须写"这个答案会怎样改变结论"**，写不出来的探针不要问。

优先级从高到低：

1. **问权限**（最低威胁、最高价值）："上次这类事，通常是您这边定，还是要走流程？" / "这份东西最后是谁签字？"
2. **问决策标准**："您评估这类方案，最看重哪一点？" / "如果这次没成，通常是因为什么？"
3. **问真实顾虑**："您觉得最大的风险在哪？" / "您内部会有谁有不同意见吗？"
4. **问时间**："您希望什么时候能看到结果？" —— 时间压力是最诚实的信息。
5. **问下一步**（**每次都问，且必须要到具体的东西**）："下一步您希望我做什么？"

**低威胁问法与高威胁问法对照：**

| 别问 | 改问 | 为什么 |
|---|---|---|
| "您到底怎么想的？" | "如果要往下走，还差哪一步？" | 前者要表态，后者要信息 |
| "能定下来吗？" | "您这边定完之后，还需要谁过一下？" | 把"能不能"变成"流程是什么" |
| "您是不是觉得贵？" | "跟什么比，您觉得不划算？" | 不预设结论，拿到比较基准 |
| "您还考虑我们吗？" | "上周那份方案，有哪一条是不成立的？" | 把评估变成内容讨论 |
| "什么时候能给答复？" | "您内部大概什么时候讨论这件事？" | 问流程，不催人 |

**关键技巧：探针要问"流程和标准"，不问"态度和意愿"。** 意愿问题会逼对方说客套话，流程问题会给你事实。

### C. 修复型（有情绪或误解）

结构：**先说你理解到了什么损失 → 再给一个能确认的动作或时间 → 不解释原因。**

- "王工，这次交付延了两天，耽误了你们上线的准备，这个是我们这边的问题。我现在能做的是：明天中午前把测试环境补齐，我本人盯着。您看这样能不能先把影响压住？"

要点：修复型话术里**不要出现"因为"**。第一次沟通里的任何理由都会被读成推责。

## 三、禁忌清单

不要给通用建议（"不要太强势""注意礼貌"），要写**这个局面下具体不要做的那件事，以及为什么**。

常见的高价值禁忌：

| 不要 | 为什么 |
|---|---|
| 不要在探清决策权之前报价 | 报价一旦落在非决策者手里，就变成了内部比较的素材，而你不在场 |
| 不要用"你不懂""你误会了"开头 | 对方会立刻从讨论内容转为保护面子 |
| 不要连续追问 | 沉默或推脱是信息，追问会把信息变成对立 |
| 不要在对方刚拒绝时立刻给新方案 | 他刚关上门，你推新的东西只会让他加固立场 |
| 不要在群里/公开场合催进度（平级与向上） | 公开催 = 公开施压，会换来一次性服从与长期不配合 |
| 不要在没有新信息时重复上次的话 | 重复沟通不产生新信息，只产生疲惫 |
| 不要替对方承诺内部的事（"您就说是我说的"） | 把他推到风险位置，短期有效、长期受损 |
| 不要在对方情绪高点上谈条件交换 | 会被读成"你是来推责的" |
| 不要贬低竞品或前任供应商 | 对方会想"以后你也会这么说我" |
| 不要把用户的情绪判断当事实写进结论 | "他就是看不上我们"不是判断，是情绪 |

## 四、三种最常见的坏话术（自查）

1. **说服型**：长篇论证自己多好。对方在做取舍时不缺你的材料，缺的是他自己的理由。
2. **紧迫型**：制造虚假稀缺（"这个价明天就没了"）。**一律禁止**：短期可能有效，但一旦被识破，关系不可逆。真实的时间压力可以说，编造的不行。
3. **劝服型**：讲道理证明对方想错了。人不会被说服，只会被自己算清的账说服。

## 五、四问自查（每条话术过一遍）

1. **它推进哪一环？** 说不出来就删。
2. **对方看到这句，会怎么理解**（不是你怎么想，是他会怎么读）？
3. **最坏情况是什么，兜底话是什么？**
4. **目的检验：对方事后知道我的完整判断，这句还站得住吗？** 站不住就重写。

## 六、该劝退时就劝退

**不要默认用户想听"还有机会"。** 出现下面这些信号，直接建议止损，并给出怎么体面收尾：

- 明确拒绝两次以上，且第二次比第一次更干脆
- 三环逐一排查后，**没有一环是可解决的**（没需求、没权限、也没有可化解的顾虑）
- 对方连低成本动作都不给（不见、不看、不回）
- 用户已经投入的沉没成本远大于这一局可能的价值
- 用户开始用"再试一次"来缓解自己的焦虑，而不是因为有新信息

劝退的正确交付：一句人话的结论 + 一个体面收尾的话术 + 一条"什么信号出现时可以再来"的复核条件。

| 收尾话术 | 用途 |
|---|---|
| "明白，那我不占您时间了。如果后面这方面的需求有变化，我随时都在。" | 保留未来可能，不结怨 |
| "这次没对上节奏，是我们的问题。您这边如果遇到 XX 情况，可以直接找我。" | 把失败归因于节奏而非对方 |

**保留关系本身就是结果。** 商务是重复博弈，体面退出比勉强推进值钱。
