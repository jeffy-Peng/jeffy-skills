# 摄取协议：聊天记录 / 消息

用户贴聊天记录时，先找**结构**，再看内容。消息类材料的价值有一半在元数据里。

## 一、先读元数据（不用读内容就能判断的）

> 沉默、延迟、已读不回的系统读法见 [signals.md](signals.md) 第 1 节（三栏对照：能做的推断 / 不能做的推断 / 该怎么验证）。本节只讲聊天记录特有的部分。

| 看什么 | 为什么 |
|---|---|
| **谁先发起** | 每次对话的发起方通常是需求方。他主动找你，还是你每次都主动？趋势比单次重要。 |
| **回复间隔的变化** | 同一话题内从 1 分钟变 6 小时 = 优先级或权限变化（L2）。 |
| **谁在最后一条** | 你结尾他不再回 = 本轮他无话可说或不想推进，不是"他在想"。 |
| **已读不回 vs 未读** | 已读不回是 L2 明确信号；未读只说明没看到，不能解读。 |
| **消息长度对称性** | 你 200 字他 6 字，持续三轮 = 温度不对，先降温再谈推进。 |
| **撤回 / 编辑** | 撤回通常是改口或说错话，值得单独记一笔。 |
| **时间点** | 深夜回、周末回 = 他在用自己的时间处理你的事（强兴趣信号）；只在工作时间秒回 = 职业性礼貌。 |
| **群 vs 单聊** | 在群里 @ 你 = 愿意公开站台；私下问 = 还在评估，不想被人看见。 |
| **转发/拉人** | 把你的内容转给了第三方（"我问下我们技术"）= 进入实质推进（L2 强证据）。 |

## 二、再读内容（按句子类型分类）

逐条标注，不要只做摘要：

| 句类 | 例子 | 含义 |
|---|---|---|
| **具体条件** | "七月前能进吗""含税吗""三个人能不能来" | 强证据：他在计算可执行性 |
| **具体数字** | 报价、工期、人数、预算区间 | 强证据，且是可锚定的谈判坐标 |
| **具体人名** | "要问下王总""李工那边" | 决策链线索，越具体越真实 |
| **笼统赞美** | "挺好的""有前景""保持联系" | 弱证据，不构成任何承诺 |
| **含糊推脱** | "再研究研究""看情况""内部再讨论" | 需要探针：缺信息、缺权限、还是缺意愿 |
| **谈条件 / 提要求** | "你们能再让一点吗""能不能先试用" | 开始谈条件 = 真实兴趣的核心标志 |
| **提顾虑 / 风险** | "万一效果不好""谁来负责""数据安全怎么办" | 他在替自己找能签的理由，是好事 |
| **闲聊 / 私人话题** | 天气、孩子、球赛、吐槽 | 关系投入，不推进业务；此处谈正事反而掉分 |
| **情绪表达** | 抱怨、发火、长篇解释 | 压力外溢，先处理情绪，不要接业务 |

## 三、问句清单（对你说话时，他在问什么）

他的问题比他的陈述更能说明处境：

- 问**价格/付款** → 到评估阶段了，但可能在探底
- 问**案例/客户** → 在找"别人也用"的免责证据，怕做第一个
- 问**工期/交付** → 有明确时间压力，往往是真的
- 问**售后/责任** → 怕出事被追责，卡点在"怕什么"
- 问**别人怎么看/能不能保密** → 内部政治敏感
- 反复问同一个问题 → 那是他真正的焦虑点，不是他忘性大

## 四、几个高频陷阱

- **不要用标点符号读情绪。** "好的"和"好的。"和"好的~"在不同人、不同平台差异极大，且高度个人化。除非有历史对照，否则不解读。
- **不要把客气当信号。** "辛苦你了""麻烦你了"通常只是结束语。
- **不要忽视"他主动发起的闲聊"。** 那次没谈业务的主动消息，价值常高于十次业务问答。
- **区分"这是他的原话"和"这是用户的转述"。** 用户转述的版本必须降级到 L3。

## 五、产出格式

先输出一张**时间线骨架**（谁先发起 / 间隔 / 最后一条是谁 / 话题切换点），再输出按句类分类的 L1 摘录，然后才进入判断。

材料不足（只有三五条消息）时，明确告诉用户"这几条只能支持什么、不能支持什么"，并直接给出：**要让判断可靠，还需要哪一条信息**——通常是"他主动说过的一句关于下一步的话"。
