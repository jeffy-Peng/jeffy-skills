# 档案维护协议

一次判断是点，档案是线。这份协议规定**线怎么长出来、怎么不被写坏**。

不维护档案的后果很具体：每次对话从零开始推，第 5 轮把第 2 轮的结论再推一遍，误差累积，最后档案变成一堆互相矛盾的碎片，用户干脆不再用它。

## 一、三条基本法

| 规则 | 含义 | 违反后果 |
|---|---|---|
| **追加而非覆盖** | 事实只追加，不做改写 | 覆盖后看不到"当初凭什么这么判断"，误读模式无法被发现 |
| **视图每次重算** | 三轴判断是从账本**推导出来的视图**，不是独立事实 | 判断与证据脱钩，几个月后没人知道它从哪来 |
| **状态而非流水账** | 档案记的是当前有效状态 + 一条沿革，不是聊天记录备份 | 档案无限膨胀，用户不再打开它 |

判断**可以**被改（而且应该被改），但必须留痕：不写"上次判断取消"，而写"上次判 X，因为 Y 证据不足，现改为 Z"。

## 二、两级结构：账本（事实）与视图（当前状态）

同一个 `dossier.md` 里，两级的性质完全不同，必须分区：

**① 事实区（事件日志，只追加，不修改）**

- 对象基础信息（标识、别名、关系、角色）
- 事实账本 L1 / L2
- 主观记录 L3 / L4
- 淘汰区：曾采用、后被推翻的判断
- 沿革：角色、决策权、关系阶段的变化时间点

**② 视图区（每次重算，可整体改写）**

- 三轴判断 + 卡点定位 + 置信度 + **有效期**
- 决策链
- 趋势
- 探针队列
- 当前阶段、时间压力方

维护动作永远只有两种：**往事实区追加一条，然后把视图区重算一遍。**

## 二之补：双时相——把"这个人"和"他的处境"分开

**同一句话在不同处境下意思相反，所以这两样必须分开存、分开更新。** 混成一个"人物画像"，是档案随使用越来越不准的头号原因。

| 时相 | 存什么 | 更新频率 | 归零条件 |
|---|---|---|---|
| **相对稳定的（他是谁）** | 说话方式、决策风格、答复快慢、给承诺的习惯、重复出现的行为、他偏好的沟通形态 | 慢，需要 3 次以上才成立 | 极少归零 |
| **当前状态（他现在处在什么处境）** | 位置与角色、KPI 与压力、时间压力在哪边、组织环境、上级与预算变动、当前阶段 | 快，处境变了就重算 | **处境一变，这一相整体作废** |

**关键推论：处境变化时，不要修改"他是谁"，而要重置"当前状态"。** 一个人被提拔之后说话变慢，不是他的风格变了，是他的处境变了——如果你把它当成风格变化写进画像，以后见到同样处境的新对象，你会完全失去可迁移的经验。

**处境特征这样记录**（填在档案的「处境特征」栏），它们是跨人比对的唯一依据：

```
处境特征：决策链位置=传话人 | 有否决者=是(技术) | 时间压力=无
          组织环境=国企流程 | 面对上级=强 | 当前阶段=评估中
```

**写法对照：**

- ✗ "他比较谨慎" → 这是标签，无法迁移，也无法验证
- ✓ "他两次向第三方确认后才表态；他给承诺时从不说时间" → 这是可观察模式，能迁移到下一个同处境的人

## 三、什么时候更新（什么时候形成模式）

不是每次说话都更新。按下面八个触发点：

| # | 触发点 | 优先级 | 说明 |
|---|---|---|---|
| 1 | **判断被推翻**（他做了与判断相反的事） | ⚠️ 最高 | 不记就白学了一次。这是档案里最值钱的两类记录之一 |
| 2 | 一件"事"完结（会谈后 / 收到明确答复 / 被明确拒绝 / 价格谈定 / 拿到或丢掉承诺） | 高 | 以**事**为单位落盘，不以对话为单位 |
| 3 | 对方角色或决策权变化（升职、换部门、换对接人、拉进新决策者） | 高 | 直接让"能不能定"那一环作废，必须重算 |
| 4 | 上次判断的有效期到了 | 中 | 状态降为"待复核"，下次接触前先做一次低成本验证 |
| 5 | 用户自身状态发生明确变化 | 中 | 回头重审"焦虑期写下的 L3"——那是污染最重的部分 |
| 6 | 出现重复模式（同一句话/同一动作第二次、第三次） | 中 | 第 3 次起，它从"信号"变成"这个人的习惯"，性质变了 |
| 7 | 用户主动说"这个不用跟了" | 中 | 状态转"关闭"，写清关闭原因与再见条件 |
| 8 | 预判被验证（他果然这么做了） | 低但有用 | 记录它——**但只有 L1/L2 的实际结果才算验证**，用户转述一律记"未验证"（见第四节「闭合点的证据级别」） |

## 四、怎么更新（固定的四步）

每次更新都按这个顺序，不要跳步：

1. **追加**：把新的 L1/L2 原文写进账本，带日期。L3 带当时状态标签。
2. **对照**：逐环检查新证据对现有判断是 **支持 / 削弱 / 否定**。三环各判一次，不要整体感觉。
3. **重算**：支持 → 置信度维持或上调；削弱 → 下调；否定 → 旧判断移入淘汰区，并写清"哪条证据否定了哪条判断"。
4. **刷新视图与索引**：改三轴、有效期、探针队列；同步更新 `insight/index.md` 那一行。

**第 2 步最容易偷懒。** 三环各判一次，是为了防住"整体感觉变了但说不清哪一环变了"——那通常意味着你在被情绪推动，而不是被证据推动。

### 闭合点的证据级别（最高优先级的一条）

**预测链的闭合点是整套系统唯一的输入，而它永远是一条用户叙述。** 所以对答案时必须分级，否则学习回路会自我认证：

| 你手上的"实际结果"是什么 | 允许写的结论 | 能否进规律库/校准账本 |
|---|---|---|
| 聊天原文、截图、邮件、第三方确认、可观察动作（L1/L2） | 成立 / 部分成立 / 不成立 | **能** |
| 只有用户的回忆与转述（L3） | **一律写"未验证"**，不得判成立 | **不能**；可进淘汰区，但必须标"未验证" |
| 没接触、没新信息 | 未验证（不是"不成立"） | 不能 |

**这么规定的理由：** 如果只凭用户一句"他还是没理我"就判"不成立"，档案里会积累一条从未被验证的失败，然后被晋升成"规律"。**宁可让预测永远停在未验证，也不要让它被错误地闭合。**

**用预测链的闭环做自我验证是无效的：** 你按建议发了一条消息，对方回了——这可能是被你的行动**制造**出来的反应，而不是被你的判断**预测**到的。所以"成立"只说明这次动作有效，不说明你读人准。

### 忙的时候可以少做哪一步（明确定义降级，而不是留给人性）

**这四步全部做完是理想状态，不是及格线。** 现实里用户在忙的时候只会做一部分，所以必须提前说清哪些可以省、哪些绝不能省——否则整套机制会在被跳过时**静默失效**：看起来还在工作，其实已经在给错建议。

| 步骤 | 忙的时候 |
|---|---|
| 追加事实 | **不可省**。这是全部记忆的唯一原料；不写，后面全废 |
| 写赌注 / 对答案 | **不可省**（档一就一行，10 秒） |
| 三环各判一次 | 可降级：只判**卡点那一环**，另两环标"未复核" |
| 重算视图 | 可降级成一句"现判断：……" |
| 晋升 / 刷新档位 | 可延后，攒着下次一起做 |
| 刷新索引行 | **不可省**，但可以只改"最近接触 + 一句话卡点"两个字段 |

**静默失效的三个征兆**（**逐对象检查**，不要看整张索引——同时跟三条线时，"最近接触"对其中两条永远是旧的，那样查必然误报）：

1. 这个对象的账本/流水行**比上次没有任何新增**（说明事实没记，后面全废）；
2. 预测栏**连续两轮空白**（说明闭环没在跑，判断没被检验）；
3. **答案栏里全是"未验证"，或级别栏全是 L3**（说明你从来没有拿到过可观察的反馈——这是最严重的一个，意味着整个学习回路在空转，账本只在记录用户自己的说法）。

出现任一条，先停下来补这一步，不要继续往下写新判断。

## 五、同一件事的多轮：一张卡承载一个"局"

**轮次不是新档案，是同一张卡上的新条目。** 这是防止碎片化的关键。

| 情况 | 正确做法 |
|---|---|
| 同一件事又谈了一轮 | 在原卡上追加一条"轮次记录"，**不新建卡** |
| 出现阶段性胜负（他明确答应 / 明确拒绝 / 说"再等等"） | 开新卡，旧卡标结局 |
| 换了新议题（从采购谈到合作分成） | 开新卡，档案不变 |
| 换了对接人但还是同一件事 | 原卡追加，档案里更新决策链 |

卡内固定维护一条轮次线，这是跨轮累积效应的落点：

```
## 轮次记录
| 轮次 | 日期 | 我做了什么 | 他做了什么 | 判断变化 |
| 1 | 4/02 | 首次见面讲方案 | 追问数据打通两次 | 初始判断：意向中 |
| 2 | 4/18 | 发边界说明 | （未回） | 卡点确认为"怕"：无交差材料 |
| 3 | 4/25 | 带技术对接 | 拉了王工进来 | 卡点转移为"不能定"：进入评估流程 |
```

**读轮次线比读任何单次判断都有用**：卡点会转移（从"怕"移到"不能定"是典型的推进信号），而只有横着看才看得出来。

## 五之二、三层晋升：从"记录"到"规律"

**记录不会自己变成更准的建议。** 一条观察要经过三次晋升，才配影响下一次判断。这是整个 memory 的核心机制：

| 阶段 | 内容 | 晋升条件 | 它能做什么 |
|---|---|---|---|
| **观察** | "他这次做了 X" | — | 只能描述过去 |
| **模式** | "他在 Y 情况下做 X" | 同一模式出现 **3 次** | 可以**预测**下一次 |
| **规律** | "处境为 Z 的人，在 Y 情况下通常做 X" | **3 个不同对象**复现，处境特征逐字相同，各有 L1/L2 结果 | 可以**迁移**到新人身上 |
| **用户规律** | "你在 W 类处境下会系统性读错" | 淘汰区出现 **3 次同类错误** | 可以**拦住你自己** |

**为什么门槛是 3 次：** 第 1 次是巧合，第 2 次是线索，第 3 次才是行为方式。**没到 3 次的观察，一律不许写成"他就是这样的人"。** 这条门槛的作用是防止档案变成一堆个人偏见——过度概括比没有记忆更危险，因为它会自我强化。

**晋升时要问的一句话：** "这条东西下次能用在哪个人身上？" 答不出来的，就只是一条备注，不要放进模式栏。

## 五之三、预测链闭环：让每次判断都被检验

**这是 memory 从"记录"变成"学习"的唯一开关。** 每做一次判断，都要留下可检验的赌注：

```
观察   4/02  他追问数据打通两次
  ↓
推断   卡点在"怕什么"：他需要能向上交差的材料
  ↓
下注   给他一份边界说明 → 预测他会回复并推进
  ↓
结果   4/18 未回；4/25 带技术的人进来 → 部分成立
  ↓
修正   卡点是"怕 + 不能定"，不是单纯的"怕" → 置信度中
```

**三条硬规定：**

1. **每次给建议时，写一句可检验的预测**（"我预计他会……"）——哪怕只是"他大概率还是不回"。
2. **每次接触后必对上一条预测的答案**（成立 / 部分成立 / 不成立 / 无法判断）。
3. **不成立的必须进淘汰区**，并写清被哪条证据推翻。

**没有闭环的档案，只是聊天记录的高级版。** 有了闭环，档案才会开始告诉你两件真正值钱的事：**这个人什么时候会动**，以及**你在哪类人身上系统性地看错**。

## 五之四、三层记忆：越用越准靠的是跨对象，不是单个档案

单份档案只能让"同一个人"越来越准。要让**新客户**第一次就有质量，必须另外两层：

| 层 | 位置 | 内容 | 作用 |
|---|---|---|---|
| **对象档案层** | `insight/<对象>/dossier.md` | 这个人的事实、处境、模式、预测链 | 对同一个人越用越准 |
| **规律库层** | `insight/patterns.md` | 跨对象规律（按**处境特征**索引）+ 经 3 次验证的有效话术 + 用户的系统性误读 | **让新人第一次就有判断** |
| **校准账本层** | `insight/calibration.md` | 预测与行为的一致率（分处境统计）+ 有效话术命中率 | 告诉用户**他的直觉哪里不可靠** |

模板见 [../assets/cross-person-patterns.md](../assets/cross-person-patterns.md)。

### 规律库层：冷启动靠处境相似，不靠性格相似

**遇到新对象时，先匹配处境，再看人。** 这是冷启动的唯一可靠办法。

匹配顺序（从上到下，优先级递减）：

1. **决策链位置**（拍板者 / 评估者 / 传话人 / 使用者）
2. **有没有否决者**
3. **时间压力在哪一边**
4. **组织环境**（流程型 / 灵活型）
5. **他对上级的暴露程度**

**不要按性格或行业匹配。** "他也挺谨慎的"没有可迁移性；"他也是传话人、上面有个技术否决者、自己不着急"才可迁移。

规律库里的每一条都必须带**适用处境**和**失效条件**，否则它会变成一个偏见的放大器：

```
规律：传话人 + 无时间压力 + 有技术否决者 → 他不会主动推进，沉默不是拒绝
     适用：初见后 2–6 周的沉默期
     失效：他主动引入了技术方（说明进入评估，性质改变）
     来源：3 个对象验证（科技公司-刘、制造-B集团-陈、医疗-赵）
```

### 校准账本层：给用户一面镜子

这是整套 memory 里**最可能让他惊讶、也最有价值**的一层：它统计的不是客户，是**用户自己**。

| 统计项 | 用途 |
|---|---|
| 预测与行为的一致率（分处境） | "你在传话人型对象上，预测与他实际行为一致 40%，在拍板者型上 75%"（**这是自洽性，不是你读人的准确率**） |
| 哪一类错误最常犯 | "你 4 次把权限问题读成了意愿问题" |
| 哪句探针真的换回了信息 | 命中率高的探针直接进规律库 |
| 哪句话术推进了下一步 | 有效话术版本化保存，下次直接复用 |

**统计口径要诚实：** 样本少于 5 次不下结论，只写"样本不足"。校准账本的价值在于**指出方向**，不在于给精确数字——给一个假精确的百分比，比不给更糟。

**它解决的是一个用户自己看不见的问题：** 他对某类人的读法一直是错的，但每次都感觉很有道理。别人指出来他不信，**账单指出来他才会信**。

## 六、时间衰减：让旧结论过期
判断做出来的时候就写一个**有效期**，避免"三个月前的乐观结论"被当成今天的依据：

| 阶段 | 有效期 |
|---|---|
| 初识 / 第一次接触 | 2 周 |
| 评估 / 谈判中 | 1 个月 |
| 待决策 | 2 周（决策期变化快） |
| 已成交 / 续约期 | 3 个月 |

超过有效期 → 判断降为 **待复核**，下次接触前先做一次低成本验证（一条消息或一个小问题），不要直接沿用。

**档案状态**四档，写在档案头和索引里：

| 状态 | 含义 | 下次怎么处理 |
|---|---|---|
| 活跃 | 有效期内，正在推进 | 正常使用 |
| 待复核 | 超有效期 | 先验证再判断，旧判断只做参考 |
| 休眠 | 长期无接触但未关闭 | 接触前先读沿革，别假设对方没变 |
| 关闭 | 明确放弃或已完成 | 只读不写；满 6 个月移到 `insight/_archive/`，索引里保留一行 |

**长期停摆后回来的情况要特别提醒用户：** 停摆期间的空白本身就是最大的信息缺口。对方可能换了岗位、换了目标、换了预算周期。旧判断里最危险的不是"变了多少"，而是**你不知道哪里变了**。

## 七、索引：跨会话怎么找回这条线

不要靠对话记忆，也不要靠翻目录。用一张索引表：

```
insight/
├── index.md                    ← 唯一入口：先读它，再进具体档案（档一对象只有流水行，无子目录）
├── patterns.md                 ← 规律库（跨对象，档三启用）
├── calibration.md              ← 校准账本（统计的是用户自己，档三启用）
├── <对象标识>/
│   ├── dossier.md              ← 档二起才有
│   └── cards/
│       └── <YYYY-MM-DD>-<事由>.md     ← 同一局的多轮追加在同一张卡里
└── _archive/                   ← 关闭满 6 个月的对象
```

`index.md` 只放活跃与休眠对象，一行一个（字段模板见 [../assets/person-dossier.md](../assets/person-dossier.md) 末尾）：

| 对象标识 | 别名 | 关系类型 | 最近接触 | 档案状态 | 档位 | 处境特征（三项简写） | 一句话卡点 | 下次动作 |

启动时先扫索引：这一步几乎零成本，却能立刻把这一局放回趋势里（"他上次也是这么说的""上次答应的事他没做"）。

**档一对象没有 `dossier.md`**——它的全部记录就是索引行下面的流水行，这是正常状态，不是"资料不全"。

**对象标识一旦创建就不再改名。** 后来发现是同一个人的另一个身份，在索引的"别名"列里加，不要新建档案——一个人两份档案，比没有档案更糟。

## 七之二、启用阈值：复杂度按使用量生长，不按文档量生长

**这是整套设计中防止"重到没人用"的开关。** 档案的**结构**不该一次给全，应该随着使用次数生长——第 1 次接触和第 10 次接触，需要的东西完全不同。

> **编号提醒：档案档位用「档一/档二/档三」，不要写成 L1/L2/L3** —— 后者已被证据阶梯占用（L1–L4）。同一份文档里两套 L 编号是实际使用中最容易出错的地方。

| 档位 | 触发条件 | 只用这几栏 | 不许做 |
|---|---|---|---|
| **档一** | 第 1–2 次接触 | **只要一行流水（见下）** | 不建三区结构、不建模式栏、不建规律库、不建校准账本、不写沿革 |
| **档二** | 第 3 次接触，或判定要跟多轮 | 补：三区结构、双时相、模式栏、预测链、轮次线、淘汰区、索引行 | 仍不建跨对象层 |
| **档三** | 完成 5 次接触 | 加：规律库 `patterns.md`、校准账本 `calibration.md` | 无 |

**规则：不到档位就不建那一层。** 空模板不会让你更准，只会让你不打开它。

### 档一的一行流水（单轮 30 秒能做完的全部维护）

第 1、2 次接触时**不要建三区档案**——维护成本会让整个机制在第一周就被放弃。只要在 `insight/index.md` 的对象行下面追加一行：

```
4/18 【事实】他说"数据打通要看下半年规划"｜【推测】他不是拍板人｜【赌注】给他边界说明，预计他会回｜【答案】(空)｜【级别】(空)
4/25 【事实】他拉了王工进群｜【推测】进入评估流程｜【赌注】问合规边界，预计王工会提责任问题｜【答案】待下轮｜【级别】待下轮
     └ 回填 4/18 行 → 【答案】部分成立｜【级别】L2（他拉人进群，可观察）
```

**五项固定：事实 / 推测 / 赌注 / 答案 / 级别。**

**回填规则（这一条不写清，预测链就断了）：**

- **「答案」永远回填到原来那一行**，不要在新行里写结论。新行只写新的事实与新的赌注。
- 回填时**必须同时填「级别」**：L1/L2 才能写成立 / 部分成立 / 不成立；只有用户回忆（L3）→ 写**未验证**。
- 每行的「答案」可以一直空着——**空着是有效状态，不是失败。** 宁可空着，也不要凭印象补一个。

**写到第 3 行、并且至少回填过 1 次答案时**，三区结构才开始值得建（升档二）。

两个降级动作同样重要：**一次性的咨询根本不建档案**；标为"关闭"的对象满 6 个月移入 `_archive/`，索引保留一行——**你不删线，只是降级**。

### 格式版本与迁移

**档案格式会变**（本文档已从两级结构升到三区结构）。所以：

- 每份档案头部写一行 `格式: v2`（当前版本）。
- 读到低版本档案时，**先复制一份 `.bak`，再就地补齐新增栏位**——不要重建、不要丢弃已有账本。
- **老档案只补不删**：新增的"双时相""预测链""档位"栏允许留空，历史事实一条都不动。
- 索引与档案不同步时（常见：改了档案忘了改索引），**以档案为准**，反向补索引行。
- 建议把这些纯文本文件放进版本控制或定期压缩备份：**丢了档案就等于丢了这个 Skill 的全部长期价值**，而它本身没有恢复机制。

## 八、压缩规则（档案不许无限膨胀）

可以压缩的：两个月的旧 L3 主观记录压成一行摘要；同一事件的第 2、3 次接触合并成一句；已进规律库的个例可以只留结论与日期。**账本与沿革不压缩。**

但下面三样任何情况下都不能删——它们是档案的全部价值：

1. **被推翻过的判断**（淘汰区）——它记录的是**你的**误读模式；重复三次，就能看出你偏哪一类错（总高估兴趣？总把权限当意愿？），并触发晋升为用户规律。
2. **对方承诺过的事 + 有没有做到**——预测他下一步最可靠的依据，比任何性格分析都准。
3. **人的行为习惯**（说过三次以上的话、每次都用同一套推脱）——到第 3 次它就不是信号，是习惯，对你的意义完全反转。

## 九、这套 memory 什么时候真的让你更准

四层机制各解决一个不同的问题，缺一层就退回到文档层面：

| 机制 | 解决什么 | 生效前提 | 现实门槛 |
|---|---|---|---|
| 档案 + 事实/视图分区 | 这个人越用越准 | 单纯重复使用 | 3 次接触 |
| 预测链闭环 | 你的判断**被检验**并修正 | 每次都写可检验的预测，并回头对答案 | 1 次接触即可开始 |
| 规律库（跨对象） | **新客户第一次**就有判断质量 | **3 个**处境特征相同的对象，各有 L1/L2 结果 | 通常需要数月 |
| 校准账本 | 拦住自己在某类人身上的系统性误读 | 每一行 ≥5 次带 L1/L2 结果的预测（4 行 = 20 次） | 通常需要半年以上 |

**"更准"只来自第三和第四层，而这两层的现实门槛都是数月量级。** 前两层让同一个人越来越清楚，但如果不跨对象、不校验自己，第 10 个客户你仍然在从零开始——只是档案更多了。

**所以对绝大多数用户，诚实的预期是：** 第一个月你得到的是**更好的单次决策**（来自证据阶梯、三环、探针），跨对象的那部分能力要等样本攒够。**不要为了显得有用而提前启用规律库——用不起来的层比没有这一层更糟。**

## 十、收尾：一条主线，三个动作

执行细则在第四节的四步（晋升与刷新索引是其中的展开），但真正要记住的只有三个动作：

1. **事完就追加**（不是说完就追加）——事件日志变长。
2. **追加完就重算视图**（三环各判一次）——当前状态保持有效。
3. **每次判断都留下可检验的预测，下次接触对答案**（只有 L1/L2 才算成立）——这才是记忆变成判断力的地方。

**复杂度按使用量生长，规律按验证次数晋升。** 判断会被改写，事实永远不许动——所以这条线能一直用下去，而且越用越准。
