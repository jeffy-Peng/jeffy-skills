# 摄取协议：录音 / 妙记 / 逐字稿

逐字稿是这三类输入里信息量最大的，也是最容易被浪费的——大多数人的做法是让 AI 总结一遍，得到一份没人会看的内容摘要。**谈话类逐字稿要提取的是压力点，不是摘要。**

## 一、先拿到可读文本

- 本地音视频文件要的是**逐字稿**，不是本地转写：走妙记（上传音视频生成纪要/逐字稿），不要用 ffmpeg + 本地 whisper 硬转，质量与说话人分离都更差。
- 会议相关录音：先定位会议，再取纪要/逐字稿/参会人快照。
- 已有妙记或纪要 `token` 时直接读产物，并用说话人替换把"说话人 1"改成真实身份——**说话人分不清，后面所有分析都是无效的**。
- 逐字稿很长时不要整篇塞进上下文：先切出与本次目标相关的时间窗，只保留决策相关段落，其余标注跳过。

## 二、标注信号（不要直接读，先标）

读之前先做一遍机械标记。标记比理解便宜，而且不会漏：

| 标记 | 找什么 | 为什么要标 |
|---|---|---|
| ⚠️ **改口** | "这个可以……呃，还是要走流程" | 改口处是真实约束与真实顾虑的入口 |
| 🔁 **重复** | 同一问题问两次以上 | 那是真焦虑点 |
| ⏸ **长停顿** | "……"、明显语塞 | 思考、犹豫，或不愿回答 |
| 👤 **人称切换** | "我觉得"→"我们公司觉得" | 从个人立场退到组织立场，通常意味着他不愿承担 |
| 📊 **具体化** | 突然出现数字、日期、人名 | 强证据，逐条摘出 |
| 🌫 **虚化** | "后面再说""到时候看" | 回避点，记下被回避的是哪个话题 |
| ✂️ **被岔开** | 一个话题刚起就被换掉 | 谁岔开的、岔去哪，比话题本身更有信息 |
| 🗣 **独白** | 某人连续说很久 | 谁掌握时长，谁掌握议程 |
| 🎯 **收尾动作** | 会议最后 5 分钟说了什么 | 收尾承诺是最高价值段落 |

## 三、八种读法

1. **读时长分布**：谁说话多。如果他 80% 时间在讲自己的困难，这次会谈的真实主题是他的处境，不是你的方案。
2. **读提问方向**：他在收集"能不能用"的信息，还是在收集"怎么拒绝你"的信息。前者问细节，后者问原则和流程。
3. **读条件密度**：出现具体条件的段落 = 他真正在计算的段落。把这些段落单独摘出来，通常占全文不到 10%，但决定一切。
4. **读人称**：**"我"变"我们"是压力点**，"你们"变"咱们"是关系升温点。
5. **读删掉的版本**：被改口覆盖的第一版往往是他真实想说的。
6. **读没说完的句子**：被打断或被自己掐掉的话，后面接着什么话题就说明什么。
7. **读共情与推进的比例**：全程只有共情（"理解理解""确实不容易"）而无推进（无下一步、无时间、无数字）= 礼貌性结束。
8. **读矛盾**：他前面说"预算不是问题"，后面说"价格要再谈" —— 矛盾不是他在撒谎，而是**背后有个第三方**（流程、老板、财务）。矛盾点就是决策链的入口。

## 四、语气与关系温度（易过度解读，谨慎使用）

> 通用版见 [signals.md](signals.md) 第 3 节。这里只列逐字稿场景的用法。

可以观察但要降低权重、并写明限定：

- **打断**：他打断你 = 主导欲强或已听完；你打断他 = 你在丢信息。
- **笑声的位置**：在关键问题后笑，常是缓冲，不代表同意。
- **称呼变化**："张总"→"老张"是关系推进，但可能只是场合变化。
- **谁在给台阶**：一方给对方找台阶（"这个也不怪你们"）= 关系尚可，值得再谈。

这些全部属于 L2 偏弱或 L3，只能用于**调整表达方式**，不能用于判断意向。**不要用逐字稿做测谎**：紧张、疲惫、方言、网络延迟与"心虚"不可区分。

## 五、产出格式

对逐字稿，固定输出这四块：

1. **关键段落摘录**：带时间戳的 L1 原文，只摘决策相关，控制在 10 条以内。
2. **压力点清单**：每个标记（⚠️🔁👤📊🌫✂️）对应的原文位置 + 一句话说明。
3. **三环读取**：他想要什么 / 他能不能定 / 他怕什么，各写依据与反证条件。
4. **收尾段落专析**：最后 5 分钟逐句过一遍——这是承诺、推脱还是客套，几乎都在这里。

**注意：** 转录文本本身有错误率，人名、数字、专有名词最容易被转错。任何关键数字与人名，都要在判断前跟用户确认一遍原文，不要把转录错误当成证据。
