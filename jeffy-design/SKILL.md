# Jeffy Design

先把事情讲明白，再选择怎样呈现。**素材是表达规范、参考样张和参考代码；模型按实际内容设计页面。**规范约束图形含义与绘制质量，样张布局和代码参数不限制本次结构。

已有决定直接沿用，局部任务从相关步骤接续。**最多一次整稿方案判断，全部在聊天中完成，不逐页确认。**需要用户判断时一次给出受众与用途、总页数，以及每页标题、核心内容与呈现构造；收到修改后直接落实并连续制作，不再问一轮“是否确认”。用户明确要求直接做时，跳过确认。

禁止生成、打开或启动用于确认的 HTML 页面、表单、确认 UI 或服务，也不借其他 Skill 引入这些步骤。最终 HTML 是交付件，不是继续工作的审批关卡。用户主动要求逐页讨论时响应其请求，不主动设置逐页批准；必要资料确实缺失时最少澄清，不把澄清变成重复确认。

## 1. 明确用途与受众

确定给谁看、使用场合、希望读者理解什么或做什么决定，以及交付格式。只有题目时默认向初学者讲清概念与关键判断，说明假设并推进；缺失会改变目标时再澄清。

## 2. 选择主题，确定整稿问题

视觉主题与内容题目分别确定。按用户指定选择 [Theme](themes/索引.md)；无指定时默认 klein-blue。主题负责字体字号、颜色、线宽、间距与页眉页脚，素材库维护黑白灰基准。制作前读取主题并贯穿绘制，不先按其他风格做完再靠覆盖样式声称合规。绘制或维护主题时读取[主题自适应](references/主题自适应.md)，使用统一主题绘制层。写清整份材料要回答的核心问题。

## 3. 拆解问题，形成提纲

先读取现有材料，按理解顺序列出各部分标题、子问题和所需证据，再安排页数。一个部分可以跨页，相关内容也可以合页。需要整稿方案判断时，把总页数和每页标题、核心内容、主体结构与必要图形/文字一起放进上述唯一一次聊天方案；不要只给标题，后面再逐页询问构造。

## 4. 研究内容，先写明白

围绕问题查事实、机制、证据和边界。陌生或变化中的事实、无依据的数字联网查原始来源；可靠现有材料可复用。记录来源、日期与口径，区分事实、推断和教学示例；证据不足补查或缩小判断。

先写脱离画面也能讲懂的解释，再确定分页、逐页必要证据和标题。标题说清对象与具体关系，避免口号与隐喻；商业模式页带模式名称。每页明确问题、观点、解释和依据。

## 5. 决定呈现方式与阅读顺序

找出本页最难理解的关系，明确读者需要从画面看懂什么，再决定结构。结果页用数字、表格或图表给依据；方法机制页画清对象、边界、动作、对应或变化；文字已能清楚解释的内容直接组织文字。没有数据不造图表，没有关系不加连线。不要求每页都有图，但不能把段落装进方框、连上箭头就当作已经画清机制。

明确先看哪里、如何阅读、凭什么得出结论。每个组件承担独立任务；多图之间有共同对象或明确对应。信息密度以解释是否充分为准，不设字数或填满比例。页面仍有空间而关键问题未解释时，展开必要关系、证据或案例；不要用大卡片、装饰或重复总结占位，也不为填满加无关内容。

案例页必须用案例中的实际对象、数据或关系支撑观点，不能只替换名称后复述通用步骤。材料不足就标明缺项、缩小范围或并回方法页，不编造具体关系。

## 6. 读取素材规范，判断如何适配

按用途→形态查 [Catalog](assets/索引.md)，先读所选条目的规范，再看样张设计理由和参考实现。只加载本页需要的规范。使用与维护规则见[素材使用与维护](references/素材使用与维护.md)。

绘制前简短记录：**继承的规则、与样张的结构差异及理由、采用的实现方式。**实现可以直接复用、局部修改或依规范重绘；这些判断由模型完成，不让用户填表。

实际内容决定对象、数量、归属、关系和几何。不得为匹配样张删减、补造或复制对象。代码不支持某种结构时，可取用共用绘制能力重新构图；本页专用坐标不自动成为下一页模板。库里没有合适素材时，按相近规范完成表达。

## 7. 绘制、组装并应用主题

按表达重要性分配空间，严格读取所选主题。先解析主题、加载并核验实际字体，再测量文字，计算范围、比例、间距、节点、标签与图例，最后绘制和验收。素材使用字体与颜色的语义角色，不写死主题数值；切换主题后重新测量与排版，不能只替换颜色或整体缩小预览来降低字号。容量不足时重排、调整区域、换表达或分页。

保留共同对象与统计口径。表格内容居中；模块无说明时标题水平垂直居中，有说明时标题与说明左对齐。连线标签和节点说明使用共用透明遮线，随字号与布局重算。细则及现有工具见[页面组装](references/页面组装.md)。

清除示例文案，关键关系与依据放进画面。截图保留真实内容；页脚保留来源、日期和可追溯出处，引用编号一致。

## 8. 配逐字稿并试讲

每页有可直接照读的讲稿，顺着画面讲主体、机制、依据与边界，补充背景和例子。术语、数字和方位与画面一致。关键关系若只能靠讲稿补出，应补回页面。

## 9. 验收并修改

依次检查：**内容成立、图形忠实、整页可读、表达完整。**检查实际字号、对齐、遮线、图例、碰撞与越界后，隐藏讲稿再问：标题答案在画面哪里得到支持？关键关系能否沿图追清？案例具体解释了什么？是否仍要读大段文字或听讲稿才懂关键机制？

表达不过关就返回内容或呈现设计，不能仅凭无碰撞、无越界判通过。几何报告与人工表达判断分开记录；记录须对应最终文件、实际主题和真实使用流程，改稿后同步更新，不沿用另一版本的验收结论。

验收以真实内容和素材规范为准，不以像不像样张为准。内容错回研究，图型不合适回表达选择，局部问题改绘制，主次失衡改组装。自动检查、人工读图和结构变化验证分别记录，不互相代替。

## 10. 连读并交付

核对顺序、遗漏、重复、承接、来源、讲稿、格式和用户要求的版本与渠道。整稿标题须与内容范围匹配，重复页面合并；证据不足就收窄，不用通用陈述撑起“全量复盘”等过大的题目。说明实际完成和未覆盖的能力。后续页继承主题与标准，重新为自己的问题设计结构。

## 工具与维护

其他 Skill、生成器或绘图库只辅助实现，不带入额外确认流程、固定版式，也不替代本 Skill 的内容、表达和验收要求。

内置主要交付 HTML。多组件静态组装见[页面组装](references/页面组装.md)；柱线同绘图区见[页面描述](references/页面描述.md)。选择工具服从本次表达，超出生成器时允许自定义绘制，但仍保留输入、适配理由、讲稿与渲染验收。用户要可编辑 PPTX 时检查实际原生对象及备注，不把 HTML 当作原生 PPTX。静态页面不宣称继承素材全部交互或动效。

新增主题在同一份素材与数据上验证；新增素材沿用统一主题接口，未迁移的历史源件不得冒称跨主题支持。

后续素材统一执行[素材使用与维护](references/素材使用与维护.md)：提供规范、带理由的样张、参考源件和验证边界。能依现有规范适配的不另增ID；新增素材经结构变化验证后再入库。草稿状态不因文档齐全而升级，单个案例通过不推定全库可靠。
