# Jeffy Design

先明确要讲什么，再决定空间怎样使用，最后选择素材。主题统一视觉与表达语气；素材提供表达规范和画法标准；模型根据本次内容设计页面，规范不限制结构。

沿用已有决定，局部修改从相关步骤接续。最多一次在聊天中提供整稿方案供用户判断，包含用途、页数、逐页标题、内容与初步构造；收到修改后连续制作。用户要求直接做时跳过确认。不逐页索要批准，不生成或打开确认HTML、表单或服务；用户主动要求逐页讨论时按其要求共创。

## 0. 先判交付形式

三种：单图（chart）、整页稿（deck）、完整报告（report）。用户只给数据或说做张图，按单图处理；明确说稿子、提案、汇报，按整页稿；明确说报告、年报、白皮书，才按报告。有歧义就按低一档走，不自行升级。

交付形式决定后面怎么走。单图只出素材视图，不写标题页脚；整页稿走页面骨架；报告在多页基础上加结构页。

## 1. 明确受众、用途、格式与主题

确定给谁看、使用场合，以及希望读者理解什么或作出什么判断。交付默认HTML，并配逐字稿；只有题目时，默认面向非专业读者解释核心问题，说明假设后推进。只有会实质改变目标的缺失才澄清。

从[主题目录](themes/索引.md)读取适用场景。主题是设计语言，现在两套，`simple-line` 简洁线条和 `pixel-mono` 像素风。提纲里写 `theme` 选设计语言，写 `palette` 选色板，`simple-line` 目前带 `klein-blue` 和 `mono` 两个色板，不写就用默认色板。

读取主题的 `usage`、`writing`、`brush`、`palettes` 与 `formats`。`brush` 决定每一族用哪套笔触（`default` 默认、`byFamily` 按原型分、`params` 笔触参数如 `gridPx`、`shadow`）。`formats` 现在有 `slide` 和 `chart` 两种版式规格，幻灯片走页面骨架，单图只出素材。受众与使用场合决定解释深度、文案和讲稿语气。主题提示词是写作要求，不替代事实研究；用户明确的表达偏好优先。

制作前读取主题并贯穿绘制，不先按其他风格做完再靠覆盖样式声称合规。绘制或维护主题时读取[主题自适应](references/主题自适应.md)，使用统一主题绘制层。

## 2. 拆解问题，形成逐页提纲

每页要先声明数据形状（多个对象各一个值、带时间的序列、占比、正负、归属、网络、分布），按形状召回素材候选，至少比较三条主力再定，选型理由写进提纲。用后备素材必须说明主力为何不适配。

写清整份材料要回答的核心问题，按理解顺序拆成子问题，安排总页数及每页的标题、核心问题或结论和必要内容。一个部分可以跨页，相关内容也可合页；封面、目录等是否需要取决于用途与篇幅，不机械添加。

页面用 `type` 指定六种之一：`content` 内容页、`cover` 封面、`section` 转折页、`toc` 目录、`appendix` 附录、`closing` 结束页。不写默认内容页。骨架图见 `assets/skeletons/`，页面不得自己写页脚和页码位置。

提纲须共同回答整稿问题，避免遗漏、重复和范围过大的标题。初步结构可随研究调整；需用户判断时合并到上述唯一一次整稿方案，不另设逐页关卡。

## 3. 研究并明确每页内容

围绕子问题检索事实、机制、证据与边界。陌生、时变或缺少依据的信息联网核验，优先原始来源；可靠的已有材料可复用。记录出处、日期、单位与统计范围，区分事实、推断、示例；证据不足补查或收窄结论。

先写脱离画面也能讲懂的解释，明确每页的观点、对象、必要关系和证据，再组织页面文案。行业与细分市场、样本与全国、不同统计时点不得混用，多选覆盖率不当作收入占比。关键口径放在读者能找到的图注或来源中，不只留在讲稿里。

按主题 writing 写标题与正文，用具体对象、动作和因果表达判断；商业模式标题带模式名称。不要用口号、比喻、抽象词串联或重复边界声明撑内容。案例须落到真实对象与证据，不能只换名称复述通用步骤。

## 4. 按内容设计可用区域

回看本页类型对应的区域配置，`formats.slide.types.<type>.regions` 给出标题区、分隔线、内容区、页脚。内容页的区域来自主题的 page，其余五种各写自己的。先确定本页可用空间，再按解释任务划分。明确各区讲什么、主次、大致面积、阅读顺序及区域间联系。可以分栏、上下分区、图文对读或一张贯穿图形；区域数量和几何由内容决定。纵向位置落在 8 像素基线上，块间距取 24。

用简短内部说明记录区域设计与理由，可放在已有页面记录中，不增加固定表格、文件或确认步骤。区域不等于卡片或单个素材，可包含多个素材或纯文字。各页按问题安排节奏，不机械重复布局，也不为差异强行变化。

区域划分是初稿，填充后可以调整。信息密度以解释充分为准，不设填满比例；必要关系未解释就展开，不用装饰、重复总结或无关内容占空间。

## 5. 选材、适配并组装

按各区域任务查[Catalog](assets/索引.md)，先读所选素材规范，只加载本页所需条目。使用与维护规则见[素材使用与维护](references/素材使用与维护.md)。记录结构差异与实现选择的简短理由；可以复用、改造或依规范重绘，不能为省事删减、补造或复制对象。

先解析主题、核验并加载字体，再测量实际文字，按数据和目标区域计算几何、坐标轴、标签与图例。颜色、字号、线宽与间距读取主题；使用共用图例及透明遮线。表格居中；独立模块无说明时标题水平垂直居中，有说明时标题与说明左对齐。实现与失败反馈见[页面组装](references/页面组装.md)。

按任务填入图形和文字，不把几张现成页面缩放拼页。没有数据不造图表，没有关系不加连线，段落装框不等于解释机制。放不下就重分区、重排、换表达或分页，不缩小主题字号或丢信息。原工具不支持时允许依规范自定义绘制，并保留输入与验收。

回看整页是否共同支持标题：主次与阅读顺序是否合理，区域是否割裂、重复或缺少关键解释。必要时返回区域设计。清除示例文案，来源、时点与引用保持可追溯；真实照片和产品界面不机械换色。

## 6. 配逐字稿，匹配讲述顺序

每页配可直接照读的讲稿，遵循主题 writing.narration。按画面阅读路径逐区解释主体、关系、证据与结论，补必要背景和例子；术语、数字和方位与画面一致，避免逐字读表、堆数字或每页重复同一种开场。

试讲时检查指向是否清楚、区域衔接是否自然。关键关系只能靠讲稿补出时返回页面补齐；讲稿不承担隐藏关键证据的任务。

## 7. 验收、修改与交付

依次核对内容成立、图形忠实、整页可读与表达完整。实际渲染检查主题字号、对齐、遮线、图例、碰撞、越界和页眉页脚；隐藏讲稿，检查读者能否找到标题依据并追清关键关系。对照主题 writing 读一遍正文与讲稿，删空话、机械转折、反复提示和不必要术语。

内容错回研究，结构不清回区域设计，局部问题改绘制。自动报告与人工读图分开，检查记录对应最终文件；无碰撞不等于讲清楚。交付前连读核对顺序、承接、遗漏、重复、来源与讲稿，提供约定格式和渠道，说明未覆盖的能力，不把一次案例通过推定为全库可靠。

默认提供完整HTML与逐字稿，不提供PPTX导出；用户要PPTX时直接说明需要另做，不能把HTML改后缀冒充。静态输出不宣称继承原素材全部动效。

交付前按顺序跑五件事：提纲阶段 `node scripts/validate-outline.mjs 提纲.json`（缺问题或结论报 CONTENT，选了没有适配器的素材报 UNSUPPORTED）；装配后 `node scripts/verify-page.mjs 输出.html`（页面报告加整页检查，裸画页同一套）；`node scripts/check-notes.mjs 输入.json 输出.html`（讲稿里的数字必须在画面上找得到）；最后 `node scripts/embed-fonts.mjs 输出.html 输出.embedded.html` 把字体子集内嵌，并发这个自包含文件。最后 `npm run baseline` 比像素基线，画面漂移当场报出来。没装字体先跑 `bash scripts/install-fonts.sh`。

## 工具与维护入口

开工前先跑 `npm run doctor`。七项自检，缺什么自己装（Node、Playwright、Chromium、主题字体、字体子集工具、生成物一致性、验收冒烟），显示 `7/7 项就绪` 才动手。`--no-install` 只看不修。

三层结构，各改各的。

- 主题 `themes/*.json`。颜色、字体、字号阶梯、间距、圆角、线宽、`grid`（基线 8、四栏、栏距 24）、`density`（稀疏 1、常规 2、密集 3），以及 `brush` 指定每族笔触与参数。
- 笔触 `lib/styles/*.js`，登记在 `lib/styles/registry.json`。只管怎么落笔，坐标吸附、硬边、阴影。不算位置，不选颜色，不判断横竖堆叠。
- 素材 `assets/materials/<ID>.md`，一个素材一个文件，31 条全部迁完。头部机器字段（id、形态、`archetype`（几何族）、`shape`（数据形状）、`tier`（主力或后备）、`implementation`（`engine` 或 `model`）、选项、问题、最低数据），下面五节正文（语义、绘制、可调整、不适用规则、验收）。旧样张与重复规范已清理，素材库只保留 md 与示意图。
- md 只写关系与语义，不写绝对像素。缝宽、间隙、图例方块、标签栏写成「取主题的 `<键名>`」（`dividerWidthPx`、`gutter`、`swatchPx`、`labelGutterPx`），否则换主题时 md 与主题各说一个数，换笔触也会错。
- `implementation: engine` 的素材走 `renderers.js`、进像素基线；`implementation: model` 的只写 md，出稿时模型按规范手绘，不进基线，验收降一档（数据齐全、不出画布、数字与讲稿一致），而且必须把主题数值一起给它，否则它按自己的 24px、全角括号画，和引擎页不齐。
- 页面 `formats.slide.types`，六种类型各自声明区域与是否要页眉线、页脚。内容页和附录声明 `use: "page"`，引用主题 page，不复制坐标。

版面由 `lib/kit/layout.js` 分配：按类型取区域，结论行按实测文字宽度占位并向上取整到 8 像素，剩余高度按权重分给组件，组件高度向下取整保证不溢出。密度只约束由布局分配的组件数量，页面自己写了坐标的按原样走。规则 R38 到 R42 见 `docs/素材规则.md`，共 42 条。

新增素材：写 md → `npm run sync` → `npm run test:materials`（按契约自动生成用例）→ `npm run specimen <ID>` 生成 `assets/materials/specimens/<ID>.png` 示意图 → `npm run baseline` 与基线比对。新增主题：改 JSON → `npm run sync` → `npm test`；只换配色就加一个色板，不动字号与版面。

素材分两轨：`implementation: engine` 的 12 条进代码、进像素基线；`implementation: model` 的 19 条只写规范，由模型按规范绘制，不进基线，验收只查数据、越界与文字碰撞。素材库只保留规范与示意图，旧样张已清理。

素材的标准化呈现就是示意图，只有图表本身，占位类别 A 到 D，没有标题、页码、来源。页面骨架图在 `assets/skeletons/`，每种页面一张，同样只有骨架没有内容。两者都不是规范，是回归基线：几何、笔触或骨架改动后重跑 `npm run baseline`，像素差超过千分之三算漂移，确认是有意改动再 `npm run baseline:update`。

新增页面类型：在 `formats.slide.types` 加一项，声明区域和 `hasRule`、`hasFooter`；内容区和附录用 `use: "page"` 引用旧区域；再到 `assets/skeletons/` 出一张骨架图进基线。

几何留在 `lib/theming/renderers.js`，七族各一份，属于引擎。素材和笔触都不复制它，所以新增一条同族素材常常零代码，换一套笔触能一次覆盖整族。

改风格只动主题和笔触，素材 md 和几何都不跟着变。只有引入一种新的落笔质感时，才动 `lib/styles/registry.json`（一行登记）和 `renderers.js` 的笔触分派（一行）；素材实现里不许出现颜色、透明度、模糊这类数值，一律问主题或笔触要。

要做背景模糊（玻璃一类），组件必须挂在页面文档里：iframe 有自己的背景层，`backdrop-filter` 透不过去，只能做出假的雾面。落笔的多层叠加（外亮边、内侧暗边、镜面高光、投影）写在笔触里，不要写进渲染器。

加主题或加素材只改数据，然后 `npm run sync`。它生成 `lib/composition/adapters.json`、`assets/capability.json`、`build/generated/*`。生成物不要手改；`npm test` 与构建都会先跑 `sync --check`，声明改了没同步会直接停下。

- 多区域静态组装与验收：[页面组装](references/页面组装.md)。
- 新增主题与素材沿用共享接口，能力、状态与验证范围分别登记；不按方向、数量或常见参数穷举素材ID。
- 其他工具只辅助实现，不带入固定版式或额外批准流程。
