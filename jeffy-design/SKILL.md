# Jeffy Design

先明确要讲什么，再决定空间怎样使用，最后选择素材。主题统一视觉与语气；素材提供表达规范与画法；模型根据本次内容设计页面，规范不限制结构。

沿用已有决定，局部修改从相关步骤接续。整页稿与报告最多一次在聊天里给整稿方案（用途、页数、逐页标题、内容与初步构造），收到修改后连续做完；用户要求直接做就跳过确认。不逐页索要批准，不生成确认 HTML、表单或服务。

**单图走四步**：第 1 步定形式与主题，第 3 步定内容，第 5 步选材装配，第 7 步验收交付。第 2、4、6 步不适用——单图没有逐页提纲、没有页面区域、不配讲稿。不要拿做稿子的流程去做单图。

## 1. 明确受众、用途、格式与主题

先判交付形式：

| 形式 | 判断依据 | 产物 |
| --- | --- | --- |
| 单图 `chart` | 只给数据、说做张图 | 素材视图，无标题页脚、无讲稿 |
| 整页稿 `deck` | 稿子、提案、汇报、分享 | 多页页面加逐页讲稿 |
| 报告 `report` | 年报、白皮书、完整材料 | 整页稿加封面、目录、附录 |

有歧义按低一档走，不自行升级。确定给谁看、使用场合，以及希望读者理解什么或作出什么判断。一份交付只承载一个主问题；出现两个「和」就拆开。只有题目时，默认面向非专业读者解释核心问题，说明假设后推进；只有会实质改变目标的缺失才澄清。

从[主题目录](themes/索引.md)读取适用场景。现在是 `simple-line` 简洁线条，带 `klein-blue` 和 `mono` 两个色板；提纲里写 `theme` 选设计语言，写 `palette` 选色板，不写用默认色板。

读取主题的 `usage`、`writing`、`brush`、`palettes`、`grid`、`density` 与 `formats`。主题是设计语言，绘制前读取并贯穿全程，不先按别的风格做完再靠覆盖样式声称合规。维护或改主题时读[主题自适应](references/主题自适应.md)。

交付通道留到第 7 步决定，版面不变：HTML 自包含、PNG 序列贴 PPT、PDF 打印。要可编辑 PPTX 说明需要另做，不能把 HTML 改后缀冒充。

## 2. 拆解问题，形成逐页提纲

写清整份材料要回答的核心问题，按理解顺序拆成子问题，安排总页数及每页的标题、核心问题或结论和必要内容。一个部分可以跨页，相关内容可合页；封面、目录、转折页是否要取决于用途与篇幅，不机械添加。

页面用 `type` 指定六种之一：`content` 内容页、`cover` 封面、`section` 转折页、`toc` 目录、`appendix` 附录、`closing` 结束页。不写默认内容页。骨架图见 `assets/skeletons/`，页面不得自己写页脚和页码位置。

每页只承担一个判断，标题写判断不写主题词，形式是「标签：内容」，例如「类别区分：四个类别的差异集中在前两名」。页数按时间算，放映每页约一分半，二十分钟的分享十二到十四页。

提纲须共同回答整稿问题，避免遗漏、重复和范围过大的标题。初步结构可随研究调整；需用户判断时合并到那唯一一次整稿方案，不另设逐页关卡。

## 3. 研究并明确每页内容

围绕子问题检索事实、机制、证据与边界。陌生、时变或缺少依据的信息联网核验，优先原始来源；可靠材料可复用。记录出处、日期、单位与统计范围，区分事实、推断、示例；证据不足补查或收窄结论。行业与细分市场、样本与全国、不同统计时点不得混用，多选覆盖率不当作收入占比。

先写脱离画面也能讲懂的解释，明确每页的观点、对象、必要关系和证据，再组织文案。关键口径放在读者找得到的图注或来源里，不只留在讲稿。

按主题 `writing` 写标题与正文：用具体对象、动作和因果表达判断，标题带模式名称时写清名字。不用口号、比喻、抽象词串联或重复的边界声明撑内容；案例要落到真实对象与证据。

数据在画之前自检：类别是否重复、缺失值是否真的缺、单位是否一致、各分项是否可相加、合计对不对得上。

## 4. 按内容设计可用区域

回看本页类型对应的区域：`formats.slide.types.<type>.regions` 给出标题区、分隔线、内容区、页脚；内容页与附录用 `use: "page"` 引用主题 page 的坐标。先确定可用空间，再按解释任务分区：各区讲什么、主次、大致面积、阅读顺序、先后联系。可以分栏、上下分区、图文对读或一张贯穿图形，区域数量和几何由内容决定。

版面规则：纵向落在 8 像素基线上，块间距 24；密度档稀疏 1 个组件、常规 2 个、密集 3 个。结论行可写可不写，写了按实测文字宽度占位，页面不得手写高度。

区域划分是初稿，填充后可调整。信息密度以解释充分为准，不设填满比例；必要关系没解释就展开，不用装饰、重复总结或无关内容占空间。用简短内部说明记录分区理由，不加固定表格或确认步骤。

## 5. 选材、适配并组装

按各区域任务查 [Catalog](assets/索引.html)，先声明数据形状（多个对象各一个值、带时间的序列、部分与整体、流量矩阵、分布、归属、多维定位、有向步骤），按形状召回候选，读 `assets/materials/<ID>.md`，至少比较三条主力再定，选型理由写进提纲。用后备素材必须说明主力为何不适配。

两轨素材：`implementation: engine` 的 12 条由代码画，样子固定、进基线；`implementation: model` 的 19 条只有规范，按 md 的绘制与验收一节手绘，必须用上主题数值，否则和引擎页不齐。

先解析主题、核验字体，再测量实际文字，按数据和目标区域算几何、轴、标签与图例。颜色、字号、线宽、间距全部读主题；轴、刻度、单位、图例走 `lib/kit/` 的共用实现，不各写一份。

按任务填入图形和文字，不把几张现成页面缩放拼页。没有数据不造图表，没有关系不加连线。放不下就重分区、重排、换表达或分页，不缩字号不丢信息。原工具不支持时允许依规范重绘，并保留输入与验收。

回看整页是否共同支持标题：主次与阅读顺序是否合理，区域是否割裂、重复或缺少关键解释。必要时回第 4 步。清除示例文案，来源、时点与引用保持可追溯。

## 6. 配逐字稿，匹配讲述顺序

每页配可直接照读的讲稿，遵循主题 `writing.narration`。顺画面阅读路径逐区解释主体、关系、证据与结论，补必要背景和例子；术语、数字和方位与画面一致，不逐字读表、不堆数字、不每页同一个开场。一页讲稿一百五到二百五十字。

试讲时检查指向是否清楚、衔接是否自然。关键关系只能靠讲稿补出来的，回页面补齐；讲稿不承担隐藏关键证据的任务。

## 7. 验收、修改与交付

依次核对内容成立、图形忠实、整页可读、表达完整。实际渲染检查主题字号、对齐、遮线、图例、碰撞、越界与页眉页脚；隐藏讲稿看读者能否找到标题依据。

自动检查按形式选：

```sh
# 单图
node scripts/build-composition.mjs 输入.json 输出.html
node scripts/verify-page.mjs 输出.html 报告.json

# 整页稿与报告
node scripts/validate-outline.mjs 提纲.json        # 每页的问题、结论、选型理由
node scripts/build-composition.mjs 提纲.json 输出.html
node scripts/verify-page.mjs 输出.html 报告.json
node scripts/check-notes.mjs 提纲.json 输出.html    # 讲稿数字必须能在画面上找到
npm run baseline                                    # 像素漂移
```

`verify-page` 的结论分开看：页面报告看图形放没放下，整页检查看字号是否在阶梯、字体是否命中、文字是否越界、同角色跨页是否同字号、同页线宽是否统一。报 `CAPACITY` 就是放不下，回第 4 步重分区。

内容错回第 3 步，结构不清回第 4 步，局部问题改绘制。

交付按通道走，三条命令：

```sh
node scripts/embed-fonts.mjs 输出.html 输出.embedded.html       # HTML，自包含
node scripts/export-pages.mjs 输出.html build/export --scale=2   # PNG，贴 PPT
# PDF：浏览器打开 embedded.html 打印，每页一张
```

PNG 是最终交付物，导出后按原尺寸抽两页看：文字有没有截断、细线糊没糊、页脚有没有出画布。静态输出不宣称继承原素材全部动效。交付时说明未覆盖的能力，不把一次案例通过推定为全库可靠。

## 工具与维护入口

开工前跑 `npm run doctor`，七项自检，显示 `7/7 项就绪` 再动手。`--no-install` 只看不修。

三层结构，各改各的：

- 主题 `themes/*.json`。颜色、字体、字号阶梯、间距、圆角、线宽、`grid`（基线 8、四栏、栏距 24）、`density`（稀疏 1、常规 2、密集 3）、六种页面区域，以及 `brush` 指定笔触与参数。
- 笔触 `lib/styles/`，登记在 `registry.json`。只管怎么落笔，不算位置、不选颜色。现在只有默认线条笔触。
- 素材 `assets/materials/<ID>.md`，一条一个文件，31 条。头部机器字段（id、形态、`archetype`、`shape`、`tier`、`implementation`、选项、问题、最低数据），正文五节：语义、绘制、可调整、不适用规则、验收。
- 页面 `formats.slide.types`，六种类型各自声明区域与是否要页眉线、页脚；内容页与附录用 `use: "page"` 引用主题 page，不复制坐标。

素材 md 只写关系与语义，不写绝对像素。缝宽、间隙、图例方块、标签栏写成「取主题的 `dividerWidthPx` / `gutter` / `legendSwatchW` / `labelGutterPx`」；写死像素的话，换主题时 md 与主题各说一个数。

版面由 `lib/kit/` 分配：`layout.js` 按类型取区域、给结论行占位、按权重分高度；`axis.js` 管绘图区、刻度、刻度短线、箭头与单位位置；`legend.js` 管图例；`unit.js` 管单位只出现一次。几何在 `lib/theming/renderers.js`，七族各一份，素材与笔触都不复制它。

规则 R1 到 R42 见 `docs/素材规则.md`，那份清单由 `lib/composition/contract.json` 生成（`npm run gen:rules`），其中 15 条有脚本自动检查，其余是文档约束。

新增素材：写 md → `npm run sync` → `npm run test:materials` → `npm run specimen <ID>` → `npm run baseline`。新增主题：改 JSON → `npm run sync` → `npm test`。新增页面类型：加 `formats.slide.types` 一项 → 补画法 → 出骨架图 → 进基线。

示意图与骨架图都不是规范，是回归基线：素材示意只有图形本身，占位类别 A 到 D；骨架图只有骨架没有内容。几何、笔触或骨架改动后重跑 `npm run baseline`，像素差超过千分之三算漂移，确认是有意改动再 `npm run baseline:update`。

生成物在 `lib/composition/adapters.json`、`assets/capability.json`、`build/generated/`，不要手改；`npm test` 与构建都先跑 `sync --check`，声明改了没同步会直接停下。
