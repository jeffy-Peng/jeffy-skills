# Jeffy Design · 内容与表达设计

接到 PPT 或 HTML 请求，先用第 1–3 步确定任务与整稿结构。每张内容页循环执行第 4–9 步，最终在第 10 步连起来验收。单页试做和局部修改从已有决定之后接续。

## 工作入口

| 要做什么 | 去哪里 | 取用什么 |
|---|---|---|
| 根据受众选主题 | [Theme 主题目录](themes/索引.md) | 从 themes/ 主题库取配置和已登记样张 |
| 根据本页问题找组件 | [Catalog 素材目录](assets/索引.md) | 从 assets/ 素材库取样式预览、可编辑源件与应用案例 |
| 草图定稿、换肤、交付前复核 | [制作注意事项](references/制作注意事项.md) | 按当前任务检查证据、映射与交付能力 |

两个目录分别维护条目与实际文件的对应关系。先查已登记的可用状态，再决定复用、临时绘制或补充材料。

## 1. 明确材料用途与受众

从请求、已有材料和上下文确定内容主题、使用场合、给谁看、希望读者理解什么或做什么决定，以及交付 PPTX 还是 HTML。已知信息直接沿用。用户只给题目时，默认面向首次了解该题目的读者，目标是讲清概念和关键判断；用一句话说明采用的假设并推进。只有缺失信息会实质改变研究对象或任务时才追问。

## 2. 选视觉主题，明确整稿核心问题

用户指定视觉主题时按指定执行；仅描述风格时按 [Theme 目录](themes/索引.md) 匹配；未指定时默认克莱因蓝（klein-blue）。把最终标识显式写入生成输入。内容题目决定研究范围，视觉主题决定呈现风格。结合受众和用途，用一句话写出整份材料要解释的核心问题或要支持的决定。

## 3. 把核心问题拆成部分，先拟标题

按读者的理解顺序拆出若干部分，逐项写「部分标题｜要回答的子问题｜需要哪些材料」。可先估页数；一个部分可以跨页，密切相关的部分也可以同页解释。逐页共创时先讨论这份提纲；明确要求整稿时直接开始研究。

## 4. 围绕问题研究，先把内容写明白

找出答案成立所需的事实、机制、例子与边界。遇到陌生概念、变化中的产品事实或缺乏依据的数字，联网查原始发布、规则、统计或技术说明。已有可靠材料可以复用。保留「判断｜直接来源｜日期和适用口径」，分清事实、推断和教学示例。证据不足时补查或缩小判断。

先为各部分写出脱离画面也能讲懂的内容底稿，按证据多少和阅读顺序确定分页、总页数（含哪些导航页）及逐页要点，再把最重要的判断提炼成标题。商业模式页标题带上模式名称。**本步产出：有依据的标题、一段完整解释，以及必须让读者看到的证据。** 标题写清对象与具体关系，沿用材料中的术语。页脚标明来源机构、材料名称、日期及可追溯出处；引用编号全稿一致。

## 5. 决定怎样呈现，画出阅读路径

从底稿挑出读者最难靠文字理解的部分。要比较多少，用共同基线；要解释谁做决定，画角色与动作；要证明界面上能做什么，找真实截图；一句定义已经讲透时直接用文字。先想清要表达的关系，再决定是否查找柱状图、泳道或其他素材。

绘制前形成简短的页面表达说明：本页问题、核心观点、必要证据、各组件的独立任务、相互关系与阅读顺序。每个组件应增加理解；删除后没有信息损失的组件不保留。用粗草图标出先看哪里、顺着什么读、最后从哪处得出判断。若想组合流程与条形图，说明两图按哪些环节对齐，各自多回答了什么。缺耗时数据时只画有据可查的流程。

## 6. 按草图找素材，与用户讨论这一页

按「用途 → 形态」查 Catalog，核对最低材料要求，挑与阅读环境相符的样式 Sheet；实物照片或产品截图另查出处并核对可见细节。库里没有合适组件时，按当前任务采用文字、原生图形或可核实图片完成页面。

**逐页共创时，把标题、内容底稿的要点、草图和候选素材放在一起给用户看。** 说明选这张图能读出什么。只有两种画法会改变理解时才并列给出。这里是正式排版前的讨论点；用户已说“画这一页”就直接出单页样稿，明确要求做完整稿就连续推进。

素材是一套能换内容、换数据、换主题的表达标准。按「一级用途 → 二级形态」检索。[素材索引](assets/索引.md)列出正式登记的素材；目录不齐时，以本页表达为先，按相近标准用原生对象补画。一次性补画经确认有复用价值后再登记。

**一个条目维护一份共用标准和参数接口，下面可挂不同视觉方案的样式 Sheet。** 条目写明适用问题、最低材料要求、元素及含义、绘制规则和易误读条件。每款 Sheet 标明适用场景，关联黑白灰预览和可编辑或可生成的源素材。素材库只提供黑白灰一套基准，不内置主题切换按钮，换主题在生成时按 themes/ 的配置映射，验收过的主题样张可以另存为应用示例。同组样式用同一组示例数据、标题和重点，便于比较。

例如单系列柱状图，标准统一约定基线、数轴、排序、单位、数值标签和图例出现的条件与位置。实心、轮廓等样式继承这些规则。加入堆叠后，需要部分与整体的关系以及新的数据字段，应另立条目。使用具体标准时允许随数据调整轴范围、标签避让和组件尺寸，保留读数含义。定性关系图同样要定义角色、方向、动作和交接条件。产品截图保留真实界面与来源，主题作用于外部标注。

## 组件粒度与自动化

Catalog 每行登记一个可复用组件、一个素材 ID。同一组件通过参数控制方向、类别和系列数量、数值或百分比模式、排序与强调项。数据与可用空间驱动几何计算。预览可提供切换控件，同时展示多种参数效果；源代码共用。

以单系列柱状图为例，横向与纵向共用 BAR-001。堆叠柱状图的横纵方向、原值与 100% 模式共用 BAR-003。模型根据本页问题选择参数，组件负责计算并检验输入有效性。百分比模式检查分项是否可相加及总量是否为零。

新增组件前先检查现有参数能否覆盖。能自动生成的方向、数量、模式变化归入参数；确有不同阅读方式或视觉编码时再增加呈现方案，例如连续柱体与单位刻线。主题按角色映射字体与颜色。登记正式 ID 前检查是否重复，参数预览与独立组件分别标清。

后续图表组件遵循 [制作注意事项中的图表自动化标准](references/制作注意事项.md#图表自动化标准)，将本次数据与主题转换为布局及连续变换。按该标准验收后登记可用状态。

## 图表素材的自适应要求

所有图表素材都根据本次输入重新计算几何与标注，包括数值轴范围、零线、刻度间隔与精度、长度或面积映射、类别与系列间距、标签所需空间、图例排列及必要的画布尺寸。应用主题后按实际字体测量标签；标题、单位、来源和箭头遵循对应标准。数据标签、图例与图形应可辨认且互不遮挡。

固定百分比轴 0–100 等有明确含义的范围，以及用户指定的共同比较范围，可以保留；核对全部输入是否在范围内，超出时明确报告并重新处理。比较多张图时按比较任务统一比例尺。布局容量不足时优先调整区域、换行、增加画布或改用更合适的呈现形式。保留主题规定的字体和字号。

无效值和空数据给出可读反馈；零值、负值和极端值按图型的数据要求处理。100% 堆叠遇到总量为零时明确标为无占比。不同数据对象仍须保留正确统计口径。

入库前替换示例数据做实际渲染验证，按适用输入覆盖长标签、多类别、多系列、小数、大数、零值、正负边界和较窄容器。检查范围覆盖、比例正确、标签与图例碰撞、越界及主题切换；保存验证结论。未通过者留在草稿区。既有素材也按此标准复核，逐项标明通过状态，不能由一款通过推定全库通过。

## 7. 填入真实内容，套用已选主题，画成页面

组合页面先读[页面组装与四关验收](references/页面组装.md)。按表达重要性与最低可读尺寸分配空间；将数据、目标区域、主题和参数交给组件，读取容量及布局反馈。禁止把完整预览连同文字整体缩小塞进格子。放不下时调整分区或表达，不默默删数据或降字号。按草图组装组件，需要局部就取局部。把真实数据、动作、标注、口径与图源放进相应位置，清除示例文案。让关键判断容易扫读，让证据可就近核对。内容密度高时优先用对齐、分组和标注组织细节，按目标阅读尺寸确定容量。

**主题控制字体字号、颜色、页框和四类页面的统一样式。** 素材以黑白灰定义文字、普通数据、重点数据、辅助线等角色；生成时映射到当次主题。克莱因蓝主题标识为 klein-blue。热力矩阵的明度表示数值，确认回路的强调色表示关键动作；换色需保留各自含义，并以数字、标签或形状辅助识别。所选主题 JSON 是验收依据。字体与配色、各角色字号/行高/字重/字距、正文段前段后距和页眉分隔线均读取该文件。配置以 1280 × 720 CSS px 为基准；用 PPTX 原生对象时按实际画布比例换算为 pt。交付前对照实际渲染样式或 PPTX 对象属性逐项核验，记录未覆盖角色或旧版式的偏差，修正后再判通过。换主题后复查中文、英文与数字字体，以及标签容纳和对比度。用户仅要求换主题时沿用原观点、素材结构和数据。

## 8. 对着成页写逐字稿，试讲一次

每页配一段可以直接照读的讲稿。按画面顺序讲清主体、机制、依据和边界，补充必要例子。试讲时如果关键关系只能靠口头补出来，就把关系补回画面。页面和讲稿中的方位、术语、数字同步更新。

## 9. 验收单页，按反馈迭代

分别验收内容成立、组件正确、整页可读、表达完整四关。自动检查实际显示字号、碰撞、越界、区域与已声明字段一致性；人工隐藏讲稿，复述观点、指出证据、追清关系。几何通过不代表内容与表达通过。失败回到对应层处理，不累积案例补丁。隐藏备注，让目标读者指出本页答案及其画面依据。核对图形含义、标签、来源、主题和实际渲染。逐页共创时交付可看的样页与讲稿，依据反馈修订；后续页继承已认可的主题和表达原则，为各自的问题重新选材。

## 10. 连读整稿并交付

按第 3 步提纲复核顺序、遗漏、重复及页间承接。将实际输出与用户要求的格式、可编辑性、预览及逐字稿逐项核对。

单柱、单线与柱线组合优先使用[统一页面描述与生成接口](references/页面描述.md)。页面描述声明组件、数据绑定、轴与主题；统一核心管理布局与图例，构建并通过浏览器验收后交付。

黑白灰多组件组装可使用[统一组件调用与反馈](references/页面组装.md#当前实现与运行)，运行 build-composition.mjs、verify-page.mjs 和 test-composition.mjs；只在已登记能力内使用。当前为静态组装、固定文字与几何适配，不声称继承整页动效。

当前内置生成器支持 HTML、逐页截图与同源讲稿。输入按 deck.schema.json，每页写 speakerNotes。M01 支持文字、本地图片、流程、条形比较组合。从 Skill 目录运行：

~~~sh
node scripts/build.mjs deck.json index.html --notes
node scripts/shot.mjs index.html preview
~~~

用户指定可编辑 PPTX 时使用可用的原生 PowerPoint 制作路径，检查图形编辑性、备注和真实渲染。内置 HTML 命令只交付其实际支持的格式。原生 PPTX 自动构建路径须通过换主题、改文字与箭头、同步讲稿、导出预览及旧 HTML 回归后方可登记。

交付前逐项检验：
- 遮住讲稿，读者能否从页面指出答案和依据；多个模块能否按同一组标签对照。
- 数据图核对单位、分母、比例与标注；关系图核对每条关键箭头的动作和两端主体；产品图核对可见证据。
- 在实际输出尺寸查看可读性、溢出、页眉页脚和主题映射。逐页试讲，核对资料来源、顺序、文件格式与用户指定字段。
