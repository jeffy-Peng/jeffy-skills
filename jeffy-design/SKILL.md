# Jeffy Design

做设计分三件事：说清读者要得到什么判断，选对承载它的图形，把图形放进该有的版面。三层约束是主题（颜色、字号、间距）、笔触（落笔质感）、素材（图形语义与画法）。模型负责根据本次内容决定放什么、怎么排，不负责发明视觉。

三种交付共用前两步，第三步分岔，第四步合回验收。**不要拿整页稿的流程去做单图，也不要拿单图的流程去做稿子。**

沿用已有决定，局部修改从相关步骤接续。整页稿与报告最多一次在聊天里给整稿方案（用途、页数、逐页标题、内容与初步构造），收到修改后连续做完；用户要求直接做就跳过确认。不逐页索要批准，不生成确认 HTML、表单或服务。

## 0 判交付形式

| 形式 | 判断依据 | 产物 |
| --- | --- | --- |
| 单图 `chart` | 只给数据、说做张图 | 素材视图 HTML 加 PNG，无标题页脚、无讲稿 |
| 整页稿 `deck` | 稿子、提案、汇报、分享 | 多页 HTML 加逐页讲稿 |
| 报告 `report` | 年报、白皮书、完整材料 | 整页稿加结构页：封面、目录、附录 |

有歧义按低一档走，不自行升级。

**PPT 不是输出格式。** 这套东西出 HTML 和 PNG；要用在 PPT 里，按 16:9 出图再贴进去。用户明确要可编辑 PPTX 时直接说明需要另做，不能把 HTML 改后缀冒充。

## 1 共通 · 定问题与事实

确定读者是谁、看完要能回答什么或作出什么判断。一份交付只承载一个主问题；出现两个「和」就拆开。

围绕主问题取事实、机制、证据与边界。陌生、时变或缺少依据的信息联网核验，优先原始来源。记录出处、日期、单位与统计范围，区分事实、推断与示例。证据不足就补查或收窄结论，不硬凑。行业与细分市场、样本与全国、不同统计时点不得混用。

按主题 `writing` 写文案：用具体对象、动作和因果表达判断，标题带模式名称时写清名字。不用口号、比喻、抽象词串联或重复的边界声明撑内容。

## 2 共通 · 选素材与数据

先声明数据形状（多个对象各一个值、带时间的序列、部分与整体、流量矩阵、分布、归属、多维定位、有向步骤），按形状查 [Catalog](assets/索引.html) 召回候选，读 `assets/materials/<ID>.md`，至少比较三条主力再定，选型理由写进提纲。用后备素材必须说明主力为何不适配。

两轨素材：`implementation: engine` 的 12 条由代码画，样子固定、进像素基线；`implementation: model` 的 19 条只有规范，由你按 md 的绘制与验收一节手绘，必须把主题数值一起用上，否则会比引擎页大一号、括号全半角不一。

数据在画之前自检：类别是否重复、缺失值是否真的缺、单位是否一致、各分项是否可相加、合计是否对得上。这些问题先发现，比画完返工便宜。

## 3A 单图

不写提纲、不分区域、不做页面骨架、不配讲稿。

三步：定图形（素材 ID 加参数）→ 给数据 → 装配成素材视图。产出只有图形本身，占位类别用 A 到 D，不含标题、页码、来源。

放不下时的顺序：换素材 → 减少类别 → 拆图或分页。不缩字号、不省标签、不截断数值。

验收：数据完整、标签不越界不重叠、单位只出现一次、图例项数等于系列数。

## 3B 整页稿

按理解顺序把主问题拆成子问题，定总页数与每页的标题、核心问题或结论。相关内容可合页，一个部分可跨页；封面、目录要不要取决于用途与篇幅，不机械添加。

页面用 `type` 指定六种之一：`content` 内容页、`cover` 封面、`section` 转折页、`toc` 目录、`appendix` 附录、`closing` 结束页。不写默认内容页。骨架图见 `assets/skeletons/`。页面不得自己写页脚和页码位置。

每页只承担一件事。标题是「标签：内容」的形式，标签由页面给，例如「类别区分：四个类别的差异集中在前两名」。可以有一行结论句，写了才占位；不写就把空间全给图形。

先确定本页可用空间再分区：`formats.slide.types.<type>.regions` 给出标题区、分隔线、内容区、页脚，内容页与附录的坐标来自主题 page。可以分栏、上下分区、图文对读或一张贯穿图形，区域数量和几何由内容决定。

版面规则：纵向落在 8 像素基线上，块间距 24，密度档稀疏 1 个组件、常规 2 个、密集 3 个；结论行按实测文字宽度占位，不手写高度。放不下就重分区、重排、换表达或分页，不缩字号不丢信息。

逐页配讲稿，遵循 `writing.narration`：顺画面阅读路径说清主体、关系、证据与结论，数字和方位与画面一致。不逐句念正文、不逐项报数、不每页同一个开场。试讲时关键关系只能靠讲稿补出来的，回页面补齐。

## 3C 报告

整页稿的全部做法，再加三件：开头封面与目录，中段每个部分前放转折页，末尾附录放口径、来源、明细。目录条目从转折页自动推，附录页码加 A 前缀。

讲稿按部分写，不按页写，读者是按部分读的。

## 4 共通 · 验收与交付

自动检查按交付形式选：

```sh
# 单图
node scripts/build-composition.mjs 输入.json 输出.html
node scripts/verify-page.mjs 输出.html 报告.json

# 整页稿与报告
node scripts/validate-outline.mjs 提纲.json        # 每页的问题、结论、选型理由
node scripts/build-composition.mjs 提纲.json 输出.html
node scripts/verify-page.mjs 输出.html 报告.json
node scripts/check-notes.mjs 提纲.json 输出.html    # 讲稿数字必须能在画面上找到
npm run baseline                                    # 像素漂移
```

`verify-page` 的结论要分开看：页面报告来自装配层，看图形放没放下；整页检查看字号是否在主题阶梯、字体是否命中族名、文字是否越界、同角色跨页是否同字号、同页线宽是否统一。报 `CAPACITY` 就是放不下，回第 3 步重分区，不要缩字号糊过去。

字体最后内嵌，交付这个自包含文件：

```sh
node scripts/embed-fonts.mjs 输出.html 输出.embedded.html
```

自动检查过了不等于讲清楚。隐藏讲稿再看一遍画面：读者能不能只靠画面找到标题的依据。内容错回第 1 步，结构不清回第 3 步，局部问题改绘制。

交付时说明未覆盖的能力，不把一次案例通过推定为全库可靠。静态输出不宣称继承原素材的全部动效。

## 工具与维护入口

开工前跑 `npm run doctor`，七项自检，显示 `7/7 项就绪` 再动手。`--no-install` 只看不修。

三层结构，各改各的：

- 主题 `themes/*.json`。颜色、字体、字号阶梯、间距、圆角、线宽、`grid`（基线 8、四栏、栏距 24）、`density`（稀疏 1、常规 2、密集 3）、六种页面区域，以及 `brush` 指定笔触与参数。
- 笔触 `lib/styles/`，登记在 `registry.json`。只管怎么落笔，不算位置、不选颜色、不判断横竖堆叠。现在只有默认线条笔触。
- 素材 `assets/materials/<ID>.md`，一条一个文件，31 条。头部机器字段（id、形态、`archetype` 几何族、`shape` 数据形状、`tier` 主力或后备、`implementation`、选项、问题、最低数据），正文五节：语义、绘制、可调整、不适用规则、验收。
- 页面 `formats.slide.types`，六种类型各自声明区域与是否要页眉线、页脚；内容页与附录用 `use: "page"` 引用主题 page，不复制坐标。

素材 md 只写关系与语义，不写绝对像素。缝宽、间隙、图例方块、标签栏写成「取主题的 `dividerWidthPx` / `gutter` / `legendSwatchW` / `labelGutterPx`」；写死像素的话，换主题时 md 与主题各说一个数。

版面由 `lib/kit/` 分配：`layout.js` 按类型取区域、给结论行占位、按权重分高度；`axis.js` 管绘图区、刻度、刻度短线、箭头与单位位置；`legend.js` 管图例；`unit.js` 管单位只出现一次。几何在 `lib/theming/renderers.js`，七族各一份，素材与笔触都不复制它，所以同族加素材常常零代码。

规则 R1 到 R42 见 `docs/素材规则.md`，那份清单由 `lib/composition/contract.json` 生成（`npm run gen:rules`），其中 15 条有脚本自动检查，其余是文档约束。

新增素材：写 md → `npm run sync` → `npm run test:materials` → `npm run specimen <ID>` → `npm run baseline`。新增主题：改 JSON → `npm run sync` → `npm test`；只换配色就加一个色板，不动字号与版面。新增页面类型：加 `formats.slide.types` 一项 → 补画法 → 出骨架图 → 进基线。

示意图与骨架图都不是规范，是回归基线：素材示意只有图形本身，占位类别 A 到 D；骨架图只有骨架没有内容。几何、笔触或骨架改动后重跑 `npm run baseline`，像素差超过千分之三算漂移，确认是有意改动再 `npm run baseline:update`。

生成物在 `lib/composition/adapters.json`、`assets/capability.json`、`build/generated/`，不要手改；`npm test` 与构建都先跑 `sync --check`，声明改了没同步会直接停下。
