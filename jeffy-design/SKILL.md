# Jeffy Design

设计的目标是把事情讲清楚。先确定读者需要理解什么，写出有依据的内容，再决定页面空间与表达方式；主题统一视觉，素材提供语义和绘制标准，模型按本次内容重新组织，不能套样张坐标或为适应工具删减信息。

当前默认落地形态是 **可交互的 PPT 式 HTML**：按演示页组织、保留主题页眉页脚、配逐页讲稿，图形支持聚焦与关系联动。它不是长篇网页报告或通用网站。底层的内容、构图、主题与素材规范仍可复用到其他交付形式；当前不宣称已具备所有格式的实现。

## 1. 明确用途与交付

沿用已有决定，明确给谁看、什么场合使用、希望读者理解什么或作出什么判断。只有实质改变目标的缺失才澄清；只有题目时说明合理假设后推进。

默认 `deliverable:deck`，输出自包含可交互 HTML 与逐页讲稿。只要求单图时用 chart，不强加封面和讲稿；长材料是否增加封面、目录、转折与附录取决于内容，不由“报告”二字机械触发。用户指定其他格式时先确认实际支持边界。

从[主题目录](themes/索引.md)选主题，绘制前读取并贯穿全程。目前默认 simple-line 设计语言、klein-blue 色板；未指定时沿用默认。字体、字号、字重、间距、线宽、颜色与可用区域以所选主题为准，不先做其他风格再覆盖样式。

**HTML 交付必读 [PPT HTML](references/PPT-HTML.md) 与[交互规则](docs/交互规则.md)**。纯文字和证据图片不硬加交互；可选择的图表对象、节点与连线应接入统一交互，不随导出脚本静默丢失。

最多一次在聊天里提供整份方案，包含用途、总页数、逐页标题、必要内容与初步构造。用户要求直接做就继续完成；不逐页索要批准，不生成确认 HTML、表单或服务。

## 2. 拆解问题与逐页任务

明确整份材料要回答的主问题，按理解顺序拆成子问题，安排页数、每页标题、核心问题或结论与必要内容。一个部分可以跨页，相关内容也可合页，提纲应共同回答主问题，避免重复或遗漏。

标题直接写有依据的判断或具体问题，不编口号、比喻或标签句式。页数由必要内容、读者基础与使用时间决定，不按固定字数或每页时长推算。

## 3. 研究并写清内容

围绕每页问题收集事实、机制、证据与边界。陌生、时变或缺少依据的信息联网核验，优先原始来源，记录日期、单位、统计范围，区分事实、推断与示例。证据不足补查或收窄结论，不混用行业/细分市场、样本/全国、不同分母与时点。

先写出脱离画面也能讲懂的解释，明确主体、动作、关系、必要证据和本页结论，再组织图形。关键口径留在画面或图注，不能藏在讲稿里。数据先核对重复、缺失、单位、可加性及合计。

标题、正文与讲稿遵循[写作规则](docs/写作规则.md)。每句话增加事实、机制或必要解释，用具体对象和自然中文，不用抽象词串联撑信息量。

## 4. 先分配区域，再填内容

读取本页类型的主题区域，页眉页脚之外才是可用主体。先想每一区域让读者明白什么，再定主次、面积、分栏/上下/贯穿结构与阅读顺序，最后才去找素材。

信息密度以解释充分、整页可读为准，不设固定组件数或填满比例。区域不足就重新分配、重排、换表达或分页，不缩主题字号、不丢对象和关系，不用装饰和重复总结填空。

## 5. 按规范选择与绘制

按区域任务查 [Catalog](assets/index.html)，读取相关素材的 assets/materials/<ID>.md，比较适合的表达再定，不凑候选数量。图表选型可查[选图表](docs/选图表.md)并运行 select 脚本；字段形状只用于召回，不证明互斥、因果或可加性。

素材是开放规范。引擎可按真实数据与区域重算时复用；未覆盖的合法结构按规范绘制 SVG，不为适配器改错表达。方向、数量、百分比不靠穷举素材 ID 解决。

库外真实图片优先用户提供或官方来源，保留出处、日期和使用边界；普通形状、图标可直接绘制；生成插画注明示意，不冒充事实。临时素材留本次项目，不自动入库。

绘制与构建读取[页面组装](references/页面组装.md)，主题绘制与维护读取[主题自适应](references/主题自适应.md)。先加载真实字体再测量，按实际内容计算几何；轴、图例、单位与遮线复用共用实现。图形和对应标签、连线应保留交互关联。

填充后回看整页：区域是否共同支持标题、阅读是否顺畅、是否缺少必要解释。清除示例文案，来源与引用保持可追溯。单图沿用第 1、3、5、7 步，不套整稿流程。

## 6. 配逐页讲稿

沿画面的阅读顺序，逐区解释主体、关系、证据与结论，补必要背景和例子；术语、数量、方位与画面一致。不逐字读表，不堆数字，不按固定字数灌水。

关键关系不能只靠讲稿补出来；隐藏讲稿后，读者也应能理解画面主要意思。交互帮助读者追踪已呈现的内容，不能成为看见关键结论的唯一途径。

## 7. 按交付形态验收

先检查内容与图形是否忠实，再检查整页主题、字号、对齐、遮线、图例、碰撞、边界与表达完整性。逐个检查形状内部的标题与说明整体垂直居中、每页来源可点击；正文不放制作编号或英文分类标签。内容错回第 3 步，结构不清回第 4 步，局部问题改绘制。

HTML 要分别检查完整静态终态与真实交互事件；只看截图不能证明交互有效，只运行结构脚本也不能证明内容正确。嵌入字体后重验实际交付文件，保留可交互 HTML 和讲稿；PNG/PDF 仅按需另导出，不替代默认 HTML。

每次只声称本次输入和实现实际覆盖的能力。对象、来源、时点、分母、图片内部内容和复杂图形语义仍须审阅。工具与维护入口见[维护说明](docs/维护说明.md)，新增素材见[素材使用与维护](references/素材使用与维护.md)。
