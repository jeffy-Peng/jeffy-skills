# 主题自适应

## 谁维护什么

- 主题维护字体、字号阶梯、字重、行高、字距、语义颜色、线宽，以及 materials 中的间距、内边距、遮线间距、圆角、实心/轮廓和节点底色。
- 素材维护语义、形状含义、比例、标注规则、对齐、连线与遮线要求。素材读取角色，不复制具体主题值。
- 数据与可用区域决定数量、换行和几何。主题不会改写数据或关系；真实产品图不做机械换色。

因此新增同类主题只增加一份 themes/*.json，不复制素材。新增一种尚无绘制能力的风格（如手绘纹理）仍需扩展共用绘制层一次；配置不能凭空提供新的绘制算法。

## 自动执行顺序

解析并校验主题 → 核验并加载真实字体 → 按角色测量 → 计算目标区域布局 → 绘制 → 更新图例与透明遮线 → 检查最终字号、碰撞、边界与主题颜色。

缺字体返回 FONT，配置缺失返回 THEME；当前实现不支持返回 UNSUPPORTED。容量不足返回 CAPACITY/LAYOUT，交由模型重分区、重排、换表达或分页。禁止静默字体回退、缩小主题字号、丢数据或只加 CSS 遮盖错误。

## 共用接口

- lib/theming/resolve.mjs：校验配置、合并 lib/theming/defaults.json 的通用基准；主题可覆盖 materials，素材不可另建私有主题数值。
- lib/theming/drawing.js：ThemeDrawing.fonts(document, theme)；ThemeDrawing.create(svg, theme) 提供 text、measure、wrap、block、line、box、legend 等。text 使用 title/cardTitle/body/pill/source 等主题角色。
- lib/theming/renderers.js：静态区域适配器，根据实际目标像素与文字测量绘制。连线继续共用 assets/共用/line-labels.js，遮罩黑白属于透明度算法，不属于可见配色。

自定义绘制也应使用该接口。允许按本页问题重新设计几何，不能用统一接口把样张坐标当成结构上限。旧例子是快照，不会因新增主题而自动改写文件。

主题可选 materials：gap、padding、labelGap、radius 为非负像素；barMode 为 solid/outline；nodeFill 为 colors 中的角色。缺省值集中在 defaults.json。其他字体、颜色与字号沿用已有主题结构；不在素材中增加字号。

## 当前范围

区域组装中的 BAR-001/002/003/006、LINE-001、PIE-001、TABLE-001/002、TIME-001、REL-001/006、FLOW-001 共12项使用 theme-v1。支持范围由 lib/composition/adapters.json 派生到 Catalog。图形按目标区域重算，不再整体缩放后补救字号。

验证了 mono、klein-blue、rounded-mono 三套主题和同一批数据。rounded-mono 是维护机制的测试配置，使用较大的无衬线字、轮廓和圆角，不替代用户默认主题。未完成全库31项源件、同绘图区引擎和动效的迁移；它们继续保持原能力边界，不声称全部自适应。LINE-001 的面积填充尚未迁移，会明确报 UNSUPPORTED。未知选项也报错，不能悄悄忽略。组件标题作为页面 text 区域使用主题角色单独分配；非空 data.title 会返回 UNSUPPORTED，避免静默丢弃。

## 维护与验收

新增主题修改一个 JSON，然后运行：

```sh
node scripts/test-themes.mjs build/theming
```

脚本对12项适配器使用相同输入检验三套主题，包含字体角色、字号字重、线宽、圆角、轮廓、表格居中、真实重排、缺字体、缺配置与容量反馈。要验证新主题，将其标识加入脚本 themes 数组，再运行。每个最终交付件仍须实际渲染与读图；测试通过不表示任何内容、布局都能容纳。

新增素材申请 theme-v1 前，必须使用共享测量与绘制接口，加入代表输入并跑跨主题测试；保留数据、对象与关系数量的核对、容量反例和截图。生成器未覆盖时按规范重绘，不复制一套主题样式到素材，也不提升草稿状态。
