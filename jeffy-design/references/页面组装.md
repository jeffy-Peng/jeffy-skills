# 页面组装与四关验收

## 责任边界

模型负责内容、表达选择与阅读路径；组件负责局部绘制；组装层负责区域、主题、跨组件联系及容量反馈。主题控制字体字号、线宽、边距等，不能由素材自行降低文字尺寸。不要把整张预览缩小塞入页面。

## 绘制前的表达说明

每页保留 question（读者问题）、claim（核心观点）、title、components[].purpose（各组件任务）、readingOrder（按 ID 的阅读顺序）、source、speakerNotes。必要时声明跨组件 bindings。它们是模型的工作记录，不要求用户逐项填写或逐页批准。需要用户判断时，只在聊天中一次汇总整稿方案；不得用HTML、确认UI或服务设置审批关卡。

先指出本页最难理解的关系及图形应解释什么。方法机制页不能以文字卡片串联代替关键关系，案例页必须落到实际对象、数据或关系。逐项说明哪份证据支持观点；每个组件增加什么理解，删除它是否有信息损失；组件之间靠共同标签、对齐、分组或连接表达什么关系。不能为了组合而多放图。同一对象同名、同一指标同口径；直接比较时统一比例尺。共享同一系列时保持样式对应；不同含义不能强行合并图例。

空间按表达重要性与最低可读尺寸分配，不平均切格。容量不足依次考虑删除重复表达、重新分配空间、局部重排或横纵切换、换表达方式、重新分页。不得自动丢失数据、隐去关系或缩小到主题字号以下。改变含义、删除关键证据、拆页由模型决定。

## 统一调用与反馈

输入组件：id、material、purpose、data、box:{x,y,width,height}、options；labelRole 可指定主题中的标签角色，当前默认 pill。坐标基于 1280×720 页面。text 数组使用相同 box，另有 text 与 role。

返回：ok、issues、required、actual、plot、regions、result。regions 记录实际测量的标签区域和最终显示字号；required 对表格使用测量值，对图形失败仅给增加区域的估计，estimate=true，不当成精确最小尺寸。

失败类型：DATA 输入不合法；CAPACITY 区域、节点或主题字号装不下；LAYOUT 碰撞；BINDING 共同对象或字段不一致；THEME 字号不符；CONTENT 表达说明缺项；CONTRACT 调用结构无效。不能吞掉错误后宣称通过。

bindings 显式指向实际输入字段，例如：

```json
{"id":"buyer","members":[{"component":"trade","field":"nodes.1.title"},{"component":"money","field":"nodes.1.title"}]}
```

这只能检查已声明字段相等，不会自动理解两个别名是否同一主体，也不代表对所有名称、单位和系列样式完成语义审计。模型仍须核对；未声明的对应关系不会自动验证。

## 四关验收与失败归属

1. **内容成立。** 标题有证据，数字、分母、公式、单位正确；区分事实、推断、示例；核对角色动作、关键分支、判断边界。失败回到内容研究。
2. **组件正确。** 检查输入域、编码、范围、数据完整性及标签图例对应。失败回到组件；本轮适配不替代各素材已有数据边界测试。
3. **整页可读。** 最终画布下测量实际字体与字号、越界、文字碰撞、节点容纳、区域相交和页眉页脚。不同组件之间检查口径与样式。失败回到布局或主题映射。
4. **表达完整。** 隐藏讲稿，复述结论、指出画面证据并追清关键关系；审查组件的必要性和相互连接。讲稿补背景及例子，不替代图中缺失的关键关系。失败回到表达选择或整页组织。

自动报告通过不等于四关全通过。人工验收必须回答：标题的直接依据在哪里、关键关系能否追清、案例具体支撑了什么、哪些关键机制仍依赖讲稿。失败返回内容或表达设计，不以边界检查替代。记录须对应最终文件与实际主题、工具流程，改稿后同步更新。表达审查保留“检查项—观察—结论—证据截图”，由实际读图后填写，不能仅因字段存在标为通过。页面无法独立支持完整机制时，补关系或明确缩小题目，不以一句边界声明替代本来需要的关键分支。

动效单独验收：最终数据一致、文字轴线持续可见、中间帧、快速连续切换、减少动态模式；本轮静态组装适配器不提供整页动效，不能声称继承原素材交互。

## 当前实现与运行

```sh
node scripts/build-composition.mjs tests/composition/pressure.json output.html
node scripts/verify-page.mjs output.html validation.json
node scripts/test-composition.mjs regression.json
```

构建输出独立 HTML 和同源讲稿；HTML 内嵌素材生成代码，生成时不依赖草稿路径。验收失败返回非零退出码，报告保留失败原因。测试包含三页正例、无效数据、小区域、区域相交、字段不一致、缺内容说明、表格错误、长标签、非法尺寸、重复 ID 及算术复核。

已接入 BAR-001/002/003/006、LINE-001、PIE-001、TABLE-001/002、TIME-001、REL-001/006、FLOW-001，共12项，见 lib/composition/adapters.json。REL-001当前使用原方案root/children接口，另一款简洁线条方案尚未迁移。当前只验证 mono 黑白灰主题。原单图与页面引擎入口继续保留，不把未接入组件登记为已支持。

当前适配策略 fixed-text-fit：读取原生成器，在目标区域内计算几何比例，重新预留实际字形边界，固定最终主题字号和线宽；图例使用共用布局器重新排列，流程节点标题恢复中心锚点。检测失败返回原因。它不是完整的拓扑重排、坐标轴重排或自动分页求解器。复杂长标签仍可能失败，此时交由模型重新分区或换表达，不能强行缩小文字。

页面描述里的 box 由模型分配；引擎检查、不擅自改变模型的阅读设计。压力样页是回归案例，不是所有内容都应照抄的模板。测试覆盖不代表所有素材、主题、组合均验证完成。

## 表格与连线标注

表格表头和单元格（含数字）水平、垂直居中；组装层不得覆盖素材的居中规则。关系图标签字体或位置改变后必须重算遮线区域；REL-006 调用 updateNetworkLabelMasks，不能复用旧字号的静态遮罩。

FLOW-001 与 REL-006 的连线文字统一由 assets/共用/line-labels.js 维护遮线。素材绘制及动画帧更新遮罩；组装层只在调整最终字号后调用同一函数，不复制另一套遮线算法。表格居中由 table.js 生成器设置，不仅依赖预览 CSS。

## 扩展素材验证

`tests/composition/extended.json` 保留分组柱、堆叠柱、瀑布图、时间线、层级结构的组合页输入；运行 `node scripts/test-composition-extended.mjs report.json` 验证横纵参数、堆叠原值/百分比、六类三系列、零总量、负终点、日期及层级异常和小区域反馈。结果范围见 tests/composition/extended-validation.json。新能力不改变独立素材的既有登记状态；仍只覆盖黑白灰静态组装。

节点说明与连线标签共同参与透明遮线（data-node-description/data-description），仅可见文字生成断口。层级、节点和模块的数量由实际输入数组决定，验收应逐层核对数量与名称，示例排布不得反向约束内容。

## 依素材规范适配，而非受生成器约束

选材后先读取规范，记录继承规则、结构差异与设计理由。原生成器适合时复用，局部不适合时修改，差异大时使用共用绘制机制重绘。UNSUPPORTED/CAPACITY 是当前实现的反馈，不是该表达方式的禁令；可以选择自定义页面并保留输入、适配判断及验证证据，不能借此绕过内容或可读性验收。不得自动把一次性重绘注册为新通用组件。全库规范从 Catalog standard 进入；共同规则见[素材使用与维护](素材使用与维护.md)。分层结构变化案例是其中一份验证证据。
