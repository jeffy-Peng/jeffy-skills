# 素材使用与维护

## 素材的交付含义

素材提供表达规范、带设计理由的参考样张和参考实现。规范决定图形含义及必须保持的视觉规则；样张帮助理解风格；代码提供已实现的绘制能力。生成器字段与参数范围描述工具能力，不定义这种表达方式的全部合法结构。

主题维护字体、字号、字重、间距、颜色、线宽与页眉页脚。素材规范不另抄一套主题数值。绘制与新增素材遵循[主题自适应](主题自适应.md)，先加载字体再测量，使用共用角色、绘制与验收接口。素材以黑白灰维护基准；真实截图不改写为主题色。

## 使用与绘制

区域设计与选材顺序见SKILL.md；选中后读取条目standard，再看样张理由和源件。只加载本页所需。记录继承规则、结构差异及实现理由，按真实内容复用、改造或重绘，不为适应工具删减或补造对象。工具未覆盖可依规范自定义，仍保留来源、讲稿与验收。

统一绘制与验收规则只维护在[页面组装](页面组装.md)。新增实现使用[主题自适应](主题自适应.md)接口，不复制私有主题数值。

## 新增或修改素材的登记要求

先检查是否能由已有素材适配；不要按方向、数量或常见模式穷举ID。仅当语义或主要视觉编码不同且有复用价值时建立新条目。维护现有条目时不删除用户原稿，也不自动提升入库状态。

Catalog 每行一个素材，至少维护：

- standard：规范文件，包含适用问题、语义规则、绘制规则、可调整结构、参考资源、使用边界与适配验收。
- sheets：有参考样张时每款填写 rationale；已实现形态必须关联可核对的 sample，解释该样张为什么这样组织，哪些安排只属于本例。
- sources：可编辑源件或参考实现。implementationRole 写实现方式：`engine` 表示有代码、进基线；`model` 表示只有规范，由模型绘制。
- question、minimumInput：语义问题与必要材料，不能把生成器的上限冒充语义限制。
- status、evidence：入库状态与验证证据分开。evidence 保留实际行为测试与审批证据，样张另按路径查看；同步不能擦除已有证据。
- standardCoverage：规范整理和行为验证分开描述。normative 规则写全，不意味着每个素材已完成重绘测试。

同一表达标准的不同视觉形态写在规范 front matter 的 `variants` 中，统一同步到 Catalog；每款明确名称、适用/避免条件、调用参数与样张，恰有一个默认形态。Catalog 展开显示，不藏在参数名或设计理由里。选材时先 ID 后形态，具体上下文与返回值见[选图表](../docs/选图表.md)。只登记已有实现或明确模型绘制且经过审核的形态，不把试稿批量提升为正式候选。

规范中的可调整结构是开放的，不做封闭参数穷举。参考实现可不覆盖全部合法结构。重要限制必须区分“语义上不成立”与“当前代码未支持”。

声明跨主题支持的实现须使用统一主题绘制层，并加入同一数据、不同字体字号主题的回归；未迁移源件不能只改登记状态。

运行 `npm run catalog`（`node scripts/build-catalog.mjs`）检查登记与引用。它只检查规范资源契约及链接，不判断规范内容是否正确。新增素材至少用一次区别于样张的结构场景验收后再申请正式入库；已有素材本轮补规范不追溯冒称全部重验。

## 能力与状态

Catalog中的规范齐备、参考实现、登记状态和行为证据分别记录。规范入口齐备，不表示所有条目都支持统一引擎、跨主题或任意结构。目录能力由实际适配器派生，不手写提升状态；样例通过不能推定全库可靠。

已确认的原版、后续改版、主题适配和引擎接入分别记录。前序明确认可不因版本替换而作废，也不要求重新批准；后续重写版不自动继承原版认可。assets 保存原版与现用规范，草稿目录已清理，Catalog 的 approval 与各 sheet 状态说明确认范围。


## 两步选材与调用

第一步按内容关系选择素材 ID，第二步按该 ID 的 `variants` 选视觉形态。`key/name` 标识形态，`useWhen/avoidWhen` 说明取舍，`optionKind` 对应 `options.kind`，`sample` 指向样张。方向、颜色和对象数量不另建形态。

模型将已判断的本页条件写入选材输入的可选 `selection`：`presentation` 为 `research/creative`，`space` 为 `compact/ample`，`priority` 为 `precision/visual/balanced`；用户明确指定形态时填 `form`。这些是模型根据用途、主题与区域提供的上下文，不让用户填表。不能仅凭主题名称或对象数量判断空间充裕。

运行 `node scripts/select-material.mjs 输入.json --intent 比较`，输出先给素材 ID，再给 `形态选择`：候选条件、建议、状态、理由和可执行 options。无明确条件默认实心；创意用途、空间充裕且非精确读数优先时可推荐随机分节。用户指定优先于软性风格偏好；指定形态缺少空间判断或存在条件冲突时返回 `review`、空 options，不静默换成另一款。不适用语义或非法数据先修正，不能靠指定形态绕过。

将返回的 options 合并到组件原有 options，保留 direction、sort 等选项；在 purpose 中简述取舍。例如同一组数据在研究页选择 `{kind:"solid"}`，在空间充裕的创意页选择 `{kind:"rhythm"}`。脚本只是辅助判断；模型仍须读取规范，检查整页可读性。若实际画面不合适，调整区域或表达并说明理由，不能把脚本建议当成视觉质量保证。
