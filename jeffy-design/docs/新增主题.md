# 新增主题的完整方案

> 本文用 lieflat 当例子讲流程。那套主题已经移除，下面的文件清单与阶段划分仍适用于新增任何主题，只是不要把 lieflat 当成现成资产。

以 lieflat（纸灰、灰阶、Inter、无轴线、刻度柱）为例。讲清楚：一个主题要定什么、素材怎么跟着变、改哪些文件、按什么顺序做、哪里会卡住。

## 一 主题要定什么

主题是外观的全部数值来源，一份 JSON，`themes/<name>.json`。十组字段：

| 组 | 字段 | 谁读它 |
| --- | --- | --- |
| 颜色 | `colors` 十个角色：ink、body、muted、line、soft、accent、accent2、paper、inverse、muted_inv | 绘图、文字、边框、明度阶梯端点 |
| 色板 | `palettes.<name>.colors` | 同一套版式换配色 |
| 字号 | `scale`：每个角色给 size、weight、lineHeight、tracking、color | 所有文字 |
| 字体 | `fonts.latin`、`fonts.ea` | 字体加载与回退检查 |
| 页面 | `page`：canvas、title、content、source、pageNo、headerRule | 布局器与整页检查 |
| 线 | `rules.dividerWidthPx`、`headerWidthPx` | 所有描边 |
| 素材量 | `materials`：间距、圆角、雷达半径、饼半径、阶梯端点、交互调门 | 各渲染器 |
| 笔触 | `brush.default`、`brush.byFamily`、`brush.params` | 落笔质感 |
| 版面 | `grid`（基线、栏数、槽宽）、`density` | 布局器 |
| 文案 | `labels`（分隔符、来源前缀） | 来源行与标题分隔。文本风格不在这里，见 `docs/写作规则.md` |

动效与交互另有字段：`motion`（待做）、`materials.shapeDimOpacity` 一类（已做）。

## 二 素材怎么跟着变

素材写语义和几何，不写颜色和字号。所以新主题进来，素材分三类：

**甲 零改动**：只吃颜色、字号、间距、圆角的素材。换主题即换皮，验收自动跑。

**乙 只改外观映射**：语义不变，但画法与主题绑定的。比如 lieflat 用刻度柱、胶囊柱，需要主题声明「compare 族默认画法」，渲染器按声明分支。

**丙 要改几何**：主题的要求超出既有几何，比如无轴线、点阵饼，得改渲染器或加分支，素材 md 只补一句「画法随主题」。

以 lieflat 为例逐条判定。写这份的时候引擎素材是 13 条，现在 18 条：新增的 BAR-005、BAR-007、DIST-001 属于乙类（柱的画法随主题），MATRIX-001、REL-004 属于甲类（只吃颜色字号）。

| 素材 | 判定 | 具体 |
| --- | --- | --- |
| BAR-001 单系列柱 | 乙 | 需要胶囊柱（柱端圆角=柱宽一半）与刻度柱（按单位切横线）两种画法 |
| BAR-002 分组柱 | 乙 | 胶囊柱分组，组间距与柱间距由主题给 |
| BAR-003 堆叠柱 | 乙 | 分段之间留缝，颜色走明度阶梯 |
| BAR-006 瀑布 | 乙 | 连接线改发丝线，正负走两端灰阶 |
| LINE-001 折线 | 丙 | 无轴线、无网格；线端点加圆点；面积填充取消 |
| PIE-001 饼图 | 甲 | 本身无轴，只需去图例、标签带数值 |
| PIE-002 双编码饼 | 甲 | 已符合 |
| TABLE-001/002 表格 | 乙 | 竖线全去，横线只留行缝，表头改大写小字距 |
| TIME-001 时间线 | 乙 | 轴线改发丝线，节点改小圆点 |
| REL-001 层级 | 乙 | 连线改细，节点改圆角矩形 |
| REL-006 / FLOW-001 关系与流程 | 乙 | 箭头改细、标签贴线、去底框 |

19 条模型绘制素材不需要写入枚举表，因为它们本来就按 md 由模型画，主题只影响颜色与字号。

结论：13 条里 3 条甲、8 条乙、1 条丙（折线），另 1 条是 PIE-002 已符合。真正要写新几何的只有两处：柱的画法分支、折线的无轴版。

## 三 改哪些文件

按依赖顺序，一共九处，前四处是新建。

1. `themes/lieflat.json` — 十组字段全填。字体写 Inter + 思源黑，字号阶梯按纸灰风格定小一号：标题 26、图内数值 21、轴标签 11.5、来源 10.5，全部带字距。
2. `themes/lieflat.materials` 里声明 `axisMode: "none"`、`shadeRamp: ["ink", "soft"]`、`barRadiusRatio: 0.5`（胶囊）、`capsuleGapPx`。
3. `lib/styles/registry.json` 里加一条 `lieflat` 笔触登记（当前落笔由主题量决定，不新建代码文件）：支持 compare、trend、share、table，参数只留 `hairline`。胶囊柱、无轴、灰阶由 `materials.barStyle`、`materials.axisMode`、`materials.shadeRamp` 三个量控制。
4. `lib/kit/axis.js` 加无轴模式 — 保留绘图区与类别标签，跳过轴线、刻度、箭头，单位挪到角落。约 40 行。
5. `lib/theming/renderers.js` 加三种画法 — `bars()` 里加 `capsule` 与 `rung` 两个分支，`lines()` 里加无轴分支。约 160 行。
6. `lib/theming/defaults.json` 加新主题量 — `barRadiusRatio`、`capsuleGapPx`、`axisMode`、`rungPitchPx`。
7. `scripts/visual-baseline.mjs` 改成按主题分目录 — `assets/materials/baselines/<theme>/<id>.png`。不改的话换主题全部报漂移。
8. `assets/materials/baselines/lieflat/` — 13 张新基线。
9. 主题读法写进 `themes/lieflat.json` 的 `usage` 与 `writing` 字段：无轴、刻度柱、灰阶规则，`SKILL.md` 已说明怎么读。

素材 md 只动一处：BAR-001 与 LINE-001 的「绘制」一节各补一句「画法随主题声明」。语义、验收、可调整都不用改。

## 四 硬前提与风险

**Inter 必须真装**。现在机器上没有 Inter（`fc-list | grep -i inter` 为空），页面用的是系统无衬线，字形偏宽，不是 lieflat 的样子。要么装字体（`npm run fonts` 加源），要么接受近似。

**中文没有 Inter**。Inter 只覆盖拉丁，中文必定回退思源黑，混排的字重与字宽要实测，字号阶梯得按中文重测一遍。

**基线必须按主题分目录**。这是改动的第一步，不做的话新主题一开，23 张基线全部报差异，看不出真问题。

**对比度**。纸灰底配浅灰块，最浅一档容易和背景融在一起。明度阶梯端点不能取纸色，这条已写进素材规则第九节。

**验收 18 项会重跑**。`test:themes` 对每个主题跑全部引擎素材，新主题不合格会直接报出来，属于好事。

## 五 分五阶段

| 阶段 | 内容 | 产物 | 工期 |
| --- | --- | --- | --- |
| 一 | 装 Inter、写主题 JSON、改基线目录 | 能出柱、饼、表的静态页 | 半天 |
| 二 | 无轴模式 | 折线、时间线不带轴 | 半天 |
| 三 | 三种画法（胶囊、刻度、无轴线） | 柱与折线的 lieflat 版 | 两天 |
| 四 | 13 张新基线 + 全套测试 | 新主题纳入回归 | 半天 |
| 五 | 主题说明与 SKILL 索引 | 可交付 | 两小时 |

合计三到四天。阶段一二结束就能看到像不像；阶段三决定这套风格成不成立。

## 五点五 阶段一实测发现的三件事

一、笔触层现在是「登记与校验」，没有真正的落笔代码。`registry.json` 里 `line` 与 `lieflat` 都指向 `theming/drawing.js`，实际质感由主题量（圆角、线宽、填充）决定。所以 lieflat 不需要新写笔触文件，只需要一条登记加一组数值。这一点与原先的设想不同，按现状走更省。

二、柱子的颜色目前按系列角色取（accent、body、muted），不是按明度阶梯。要 lieflat 那种一片灰阶，柱子也得走 `shadeRamp`，和 PIE-002 用同一套派生色规则。

三、无轴模式没有实现时，`materials.axisMode` 只是声明，画面上轴线、刻度、箭头照样在。所以阶段一出来的页面「颜色对了，骨架还是简单线条」。

## 六 明确不做

动效与交互不进主题 JSON 的新字段之外的东西。交互已经在 `interaction.js` 里全局生效，主题只给四个调门；动效等 `docs/待办.md` 里的方案定了再做。

不做的是：为 lieflat 单独开一套渲染管线。主题是配置，不是引擎。
