# 维护说明

在 skill 根目录执行。制作主流程只看 SKILL.md，本文件只讲维护。

1. 修改主题 JSON 或素材 MD，运行 npm run sync。MD 决定条目增删与机器字段，catalog.json 保留审批、证据和展示补充字段。sources/sheets 的空数组可清空旧引用，证据不被同步重置。
2. npm run sync:check 只检查，不写；npm run catalog 生成目录 HTML 并核对资源，不改能力表。
3. npm run test:all 跑主题、组装、参数、素材和对抗反例。失败不能靠删数据或降低主题字号放行。
4. 绘制层改动跑 npm run baseline：重新构建当前源码样张再比较，缺基线或未知 ID 失败。只有审阅当前图、确认有意改动后才运行 npm run baseline:update。页面骨架和历史页面样张暂不在此自动回归范围。
5. 新引擎素材须有代表输入和数据/容量反例；模型素材不伪称引擎覆盖，按规范绘制 SVG artifact，走同一整页验收。方向、数量和百分比等参数不单开 ID。

环境使用 npm run doctor -- --no-install，Windows 也在真实浏览器核验字体。自包含交付另加 --embed；FONTTOOLS_PYTHON/FONTS_DIR 可指定工具与字体路径。字体文件来源与度量登记在 fonts.lock.json。

默认交付 HTML 和逐页讲稿。embed-fonts 按交付件实际主题嵌入用到的字体，随后对 embedded.html 再运行 verify-page，查看代表页面。静态导出不宣称带动效。

数量核对会报告待复核的背景数字；重要事实可显式 facts 绑定。对象、口径、来源、图形编码和讲稿解释仍需实际审阅，机器通过不代表内容正确。

提交在正常 Git 修复分支中完成，检查差异与测试后推送，通过 PR 审阅。push-skill.sh 不克隆覆盖，不读取 token，不清空目录，不改远端 URL；陈旧分支、脏工作树会拒绝推送。
