# Skill 结构总览

截至 2026-11-13。分四层：数据、引擎、生成物、文档。

## 定位

这是一套标准化的设计方案，不是画 PPT 的工具。输入是需求与交付形式，输出是单图、整页稿或报告。格式只是最后一步，规则、素材、笔触、验收都与格式无关。

## 一 数据层（人维护）

```
themes/
  simple-line.json     设计语言：字体、字号阶梯、间距、线宽、笔触、网格、密度
                       内含 palettes（klein-blue、mono）与 formats.slide.types（六种页面）
assets/materials/
  BAR-001.md           素材最小单元：语义、规则、shape、tier、示意图引用
  specimens/           示意图 PNG，一素材一张，只有图表本身
  baselines/           示意图基线，像素回归用
assets/skeletons/      六种页面的骨架图，content、cover、section、toc、appendix、closing
assets/pages/          简单线条页面样张，bar、line、pie、table，带完整骨架
assets/catalog.json    素材登记，BAR-001 由 md 合并，其余 30 条仍在此手写
```

素材是内容单元，主题是风格单元，笔触是落笔单元。三者各改各的，不交叉复制坐标。

## 二 引擎层（代码，一次写好长期不动）

```
lib/kit/
  layout.js            页面布局：按类型取区域、8px 基线吸附、结论行实测占位、密度上限
  legend.js            图例唯一实现：居中、换行、符号一致、超两行报容量
  axis.js              绘图区、刻度、轴线、单位；网格可关；轴线延后绘制不压内容
  unit.js              单位只在轴端出现一次
lib/theming/
  drawing.js           画笔基座：text/measure/wrap/box/line，颜色字号只能取主题角色
  drawing-fonts.js     字体核验：族名命中 + 探针字宽比对，被替换即报 FONT
  renderers.js         几何：bars / lines / table / timeline / hierarchy / graph / pie
  resolve.mjs          主题校验：色板、笔触、族支持、参数、版面区域、网格与密度
lib/styles/
  pixel-brush.js       像素笔触：坐标吸附、硬边、硬阴影，参数由主题传
  registry.json        笔触登记：支持哪些族、可接受哪些参数、fontUnit
lib/composition/
  runtime.js           装配：建页、按 type 取区域、挂组件、收集报告
  fatal.js             致命错误页：缺字体等直接画在画布上
  contract.json        42 条共用规则、尺寸上限、网格参数、错误码
  adapters.json        生成物，不要手改
lib/checks/
  page-checks.mjs      整页检查：字号阶梯、族名、越界、跨页一致、线宽按角色比较
```

## 五 脚本

```
npm run doctor                 环境自检与自修，缺什么装什么
npm run sync                   扫描主题与素材声明，生成登记、能力表、主题清单
node scripts/validate-outline.mjs   提纲校验：交付形式、shape、tier、选型理由
node scripts/build-composition.mjs  装配成 HTML
node scripts/verify-page.mjs        渲染验收：页面报告 + 整页检查
node scripts/check-notes.mjs        讲稿与画面数字比对
node scripts/embed-fonts.mjs        字体子集内嵌，交付自包含
npm run specimen <ID>          生成素材示意图（只有图表，无页面骨架）
npm run baseline               素材示意图、页面骨架、页面样张与基线比像素，超千分之三报漂移
npm run baseline:update        确认改动后更新基线
npm run test:all               主题契约 + 组装 + 适配器 + 主题 + 契约用例
```

## 六 三条日常链路

出一份稿子：判交付形式 → 写提纲（type、shape、tier、reason）→ 校验提纲 → 装配 → 验收 → 数字核对 → 内嵌字体 → 基线比对 → 交付。

加一条素材：写 `assets/materials/<ID>.md` → `npm run sync` → `npm run test:materials` → `npm run specimen <ID>` → `npm run baseline`。

改一次外观：改主题或色板 → `npm run sync` → `npm test` → `npm run specimen` 全部重出 → `npm run baseline` 确认漂移范围。

改一次骨架：改 `formats.slide.types` → 重出 `assets/skeletons/` → `npm run baseline` 看漂移 → 确认后 `npm run baseline:update`。
