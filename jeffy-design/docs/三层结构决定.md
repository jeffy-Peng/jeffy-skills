# 决定：三层结构与按族选笔触

状态：已确定。日期 2026-11-12。以后所有关于“该改哪儿”的判断都按这份走。

## 三层各管什么

**主题** 管数值。颜色、字体族、字号阶梯、字重、行高、字距、页边距、可用区域、圆角、间距、内边距、线宽、柱形实心或空心、写作语气。一个 JSON。

**素材** 管语义与结构。回答什么问题、最低需要什么数据、哪些画法算错、横向还是竖向、并置还是堆叠、百分比还是绝对值。一份声明。

**笔触** 管落笔。坐标吸不吸附格子、边缘硬不硬、加不加阴影、描边要不要、文字怎么贴网格。一份代码，按族复用。

## 判据

改一条规则只该动一个文件。要动两个说明还没归位。

举几个容易争的。圆角归主题，因为它是数值。阴影归笔触，因为它是手法。堆叠归素材，因为它是表达决定。字号归主题。图例位置由主题的间距决定，图例里写不写单位归素材。

## 笔触怎么选

不单独选。主题里按族指定。

```json
"styles": {
  "compare": "pixel",
  "trend": "line",
  "share": "line",
  "table": "line",
  "timeline": "line",
  "relation": "line",
  "flow": "line"
}
```

没写的族默认用 `line`。这样像素风可以只接管柱状，其余照旧，不会出现四不像。

## 几何的地位

几何不属于上面任何一层。它是引擎，按族各一份，写在 `lib/geometry/`。横向、竖向、堆叠、百分比这些由它算。几何写一次，所有素材和所有笔触共用。

现状是几何还留在 `lib/theming/renderers.js` 里，没搬出来。搬迁是纯结构调整，功能零变化。

## 素材契约

所有素材共用一份契约，写在 `lib/composition/contract.json`，不各写各的。

契约规定四件事。数据形状统一（类别、值、可选系列名）。方向、排序、百分比这些选项的取值集合统一。最小可读尺寸统一，柱宽低于 8px、行高低于 22px、点距低于 16px 就报容量不足。放不下时的反馈统一，报 CAPACITY 并附 required 与 available。

素材只声明自己支持哪些选项，不实现选项逻辑。

`npm run test:materials` 按契约自动生成用例，从现有样本派生基础、单条、十二条、超长标签四版，每条素材都跑同一批，不手写用例。关系与流程类素材的样本由节点和连线组成，机械复制会造出非法结构，这几类只跑基础用例。

## 色板与格式

主题是设计语言，不是配色方案。同一套设计语言可以有多个色板，写在主题的 `palettes` 里，提纲用 `palette` 选，不选就用默认色板。换配色只加色板，字号、间距、版面、笔触都不动。

格式写在主题的 `formats` 里，现在两种：`slide` 是 16:9 幻灯片，有页面骨架；`chart` 是单图，只有画框。素材与格式无关，给一块区域就能画。

## 示意图与基线

示意图是素材的最小呈现，只有图表本身，占位类别 A 到 D，没有标题、页码、来源。它不是规范，是回归基线：几何或笔触改动后重跑，像素差超过千分之三报漂移，确认是有意改动才更新基线。

## 组合关系

一页由四样决定：用哪条素材、什么结构参数、填什么数据、用哪个主题。笔触由主题派生，不增加组合维度。

组合总数等于可组装素材数乘主题数。现在是 12 乘 2，等于 24 个格子。加主题变 36，不写代码。

不是每个格子都成立。容量和对比度由验收判断，不成立要明确报错，不能悄悄画坏。

## 已验证的事实

像素笔触写完，四条柱状素材全部通过，主题按族切换生效，线条那套的 12 项组装和 23 项适配器回归数字没变。两套主题乘全部素材族 29 项全过。

字体风格的分辨率有限。族名能命中不代表用的是那个文件，所以按 `scripts/fonts.lock.json` 的探针字宽再比一次，偏了报 FONT 并说明是替代字体。

## 换风格时该做什么

只改颜色、字号、疏密：动主题。
要改边缘软硬、阴影、线条质感：写一套笔触，一次性，所有族立刻可用。
要改数据怎么组织、画哪种图：动素材，缺几何才写代码。
